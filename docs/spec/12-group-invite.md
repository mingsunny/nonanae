# 12. 멤버 초대 (그룹 내부)

> 앱 미가입 친구를 이름만으로 미리 추가해 정산에 포함시키는 기능. 대기 중 멤버 한 명당 개인화된 초대 링크를 보내서, 그 링크로 들어오면 매칭 화면 없이 바로 그 자리에 연결됨(07 삭제됨).

그룹 멤버 목록을 확인하고, 아직 앱에 가입하지 않은 친구도 이름만으로 미리 추가해 정산 계산에 포함시키는 화면.

- **상태**: 초안

## 3. UI 구성

### 3.1 멤버 목록

- 아바타: 이름 첫글자 노출
- 이름: schema.md의 이름 결정 순서 참고(대기중 또는 게스트(둘 다 `userId` 없음)=Member.name / 정식회원=User.name)
- 배지: 대기 중 멤버는 "초대 대기 중" 배지
- 대기 중 멤버는 그 옆에 "초대 보내기" 링크가 각각 붙음(멤버 한 명당 하나, 일괄 버튼 아님)
- (2026-10-17) 이미 승인된 자리(회원 계정 또는 승인받은 게스트)에는 "초대 대기 중" 배지와 "초대 보내기"가 보이지 않음 — 더 보낼 필요가 없으므로
- (2026-10-17) 참여 요청이 들어온 자리는 멤버 목록에서 빼고 위 "참여 요청" 카드에만 보임(같은 사람이 두 번 보이지 않게). 승인·거절하면 다시 목록에 정상 표시
- 본인이 게스트로 참여한 자리(`userId` 없음 + 본인)에는 "이름 수정" 텍스트 링크가 붙음 — 정식 회원은 04 프로필에서 이름을 고치므로 여기서는 보이지 않음. 다른 사람의 게스트/대기 중 자리에도 보이지 않음(본인 자리만)

### 3.1-1 참여 요청 (방장에게만, 2026-10-11 · 2026-10-17 갱신)

- 초대코드로 들어온 사람의 참여 요청이 있으면 멤버 목록 위에 "참여 요청 N" 카드가 뜬다 — 방장에게만 보인다. **승인 대기 중인 요청만** 보이고, 거절한 요청은 사라진다
- 그룹장이 알림을 안 눌러도 알 수 있게 (2026-10-17):
  - 그룹 목록([03](03-group-list.md)) 그룹 카드에 "참여 요청 N" 배지
  - 그룹 화면([08](08-group-expense-list.md)) 맨 위에 배너 "{이름}님이 참여를 요청했어요 · 확인하기 ›" (여러 명이면 "{이름}님 외 N명이"). 누르면 이 화면으로
- 행마다 아바타 + 요청한 이름 + 설명("'{자리 이름}' 자리로 참여" / "새 멤버로 참여" / "로그인 없이 · 새로 참여" / "로그인 없이 · 기존 자리로 참여") + "거절" / "승인" 버튼
- 요청이 오면 그룹에 "{이름}님이 [그룹명] 그룹에 참여를 요청했어요" 알림이 생기고, 알림을 누르면 이 화면으로 온다([13](13-notifications.md))

### 3.2 대기 중 멤버 추가

- 이름 입력하여 멤버 추가
  - 이름 (텍스트)
  - "추가" 버튼 클릭 시 멤버 목록에 추가

### 3.3 하단 버튼

- 화면 하단에 "그룹으로 가기" 버튼 고정 (항상 노출)
- 그룹 생성 직후(05에서 이동)에는 헤더 back 버튼을 숨김 — 바로 위 버튼이 유일한 출구

## 4. 기능

| 기능 | 동작 |
|---|---|
| 이름 입력 후 "추가" | 대기 중 멤버로 그룹에 추가, 목록 갱신, 토스트("{이름}님을 추가했어요") |
| 특정 멤버 옆 "초대 보내기" 클릭 | 그 멤버 전용 개인화 코드 생성 후 카카오톡 공유(또는 복사) — 이 코드로 들어오면 매칭 화면 없이 자동으로 그 자리에 연결됨 |
| 본인 자리 옆 "이름 수정" 클릭(게스트 본인만) | 이름 입력 필드로 바뀌어 새 이름을 입력하고 "저장" — 그 즉시 목록·지출·정산 화면 등 모든 곳에 반영됨 |
| 하단 "초대코드 새로 만들기" 클릭(방장만) | 확인창("이전 코드와 초대 링크는 더 이상 쓸 수 없어요") → 확인하면 새 코드 발급, 토스트("초대코드를 새로 만들었어요"). 08의 "초대 코드 복사"도 새 코드를 복사함 |
| 참여 요청 "승인"(방장만) | 요청한 사람이 실제 멤버가 됨(고른 자리가 있으면 그 자리에 연결) → 목록 갱신, 토스트("{이름}님의 참여를 승인했어요"). 요청한 사람의 승인 대기 화면은 몇 초 안에 그룹으로 들어간다 |
| 참여 요청 "거절"(방장만) | 요청을 지우지 않고 **거절됨** 상태로 남김(방장 화면에서는 사라짐), 토스트("{이름}님의 참여 요청을 거절했어요"). 요청한 사람의 화면은 "거절됨"으로 바뀌고, "다시 요청하기"로 다시 요청하면 승인 대기로 돌아오며 방장에게 다시 알림 |
| 헤더 back | 그룹 상세로 복귀 (그룹 생성 직후엔 back 숨김) |
| "그룹으로 가기" | 그룹 상세(08 지출 탭)로 이동 |

## 5. 데이터

- 멤버 목록: `Group.members`(같은 그룹의 Member 전체)
- 대기 중 멤버 추가: 새 `Member` 행 생성
  - `name`에 입력한 이름 저장
  - `userId`는 null
- 개인화 초대 코드 형식: `{Group.inviteCode}-{Member.id}`
  - 이 코드로 들어오면 초대 화면("{이름}님으로 참여하기")이 뜨고, 누르면 그 자리로 참여 요청 → 방장 승인 시 연결
  - 이미 승인된 게스트 자리를 지정해도 **승인 없이 들어가지 않는다**(2026-10-25 정정). 다른 기기·브라우저, 또는 로그인·가입으로 그 자리를 이어받으려면 방장 승인이 다시 필요하다 — 자리 ID는 초대코드만 알면 얻을 수 있어서, 승인 없이 들어가게 하면 코드를 아는 누구나 자리를 가로챌 수 있기 때문
  - 그 자리가 이미 회원 계정이면 공용 코드처럼 처리(비로그인이면 "승인이 완료됐어요. 로그인하고 사용해요.")
- 게스트 본인 이름 수정: 기존 `Member.name`을 새 값으로 교체(같은 `Member.id`를 그대로 씀 — 지출/알림 등 그 자리를 가리키는 다른 데이터는 안 건드림). 이미 만들어진 알림 문구는 그대로 남음(생성 시점 이름으로 고정 저장 — schema.md)
- 초대코드 재발급: `Group.inviteCode`를 새 값으로 교체. 이전 코드와 `{이전코드}-{Member.id}` 형태의 개인 초대 링크는 즉시 무효가 되고, 이미 참여한 멤버(게스트 포함)는 `Member` 행으로 식별되므로 영향 없음. 코드가 카카오톡 등으로 원치 않는 사람에게 알려졌을 때 끊는 용도 (초대코드를 아는 사람은 같은 그룹 멤버 일부의 계좌번호를 볼 수 있어서 — [schema.md](schema.md) "알려진 제한")

## 6. 예외 처리

| 상황 | 처리 |
|---|---|
| 이름 입력이 비어있음 | "추가" 버튼 비활성화 |
| 이름 수정 중 빈 값 | "저장" 버튼 비활성화 |
| 방장이 아닌 사람이 코드 재발급 | 버튼이 보이지 않음. 직접 요청해도 서버가 거부("방장만 초대코드를 새로 만들 수 있어요") |
| 다른 사람의 자리를 고치려는 요청 | 서버가 거부(RLS/RPC가 "지금 이 세션이 차지한 자리"만 허용) |
| 요청이 고른 자리를 그 사이 다른 사람이 차지함 | 승인이 거부되고 "그 자리는 이미 다른 사람이 차지했어요. 거절한 뒤 다시 요청해달라고 해주세요." 토스트 |
| 방장이 아닌 사람이 승인·거절 | 요청 카드가 보이지 않음. 직접 요청해도 서버가 거부("방장만 참여 요청을 처리할 수 있어요") |
| 이미 거절·승인한 요청을 다시 처리 | 서버가 거부("이미 처리된 요청이에요") |

### 그룹장 탈퇴 (2026-10-17)

- 그룹장이 회원 탈퇴하면, 그 그룹에 남은 **회원 중 가장 먼저 들어온 사람**이 자동으로 새 그룹장이 된다(참여 요청 승인·초대코드 재발급 권한도 넘어감)
- 남은 정식 회원이 없으면(게스트·대기 중 멤버만 남음) 그룹장 없는 그룹이 된다. 이 그룹은 **정식 회원이 들어올 때만 승인 없이 바로 참여**하고, 그 사람이 새 그룹장이 된다(이미 게스트가 차지한 자리는 바로 가져갈 수 없다). **게스트는 바로 들어올 수 없고** 요청만 남긴다. 승인 대기 중이던 요청은 지우지 않고, 새 그룹장이 처리한다
- 그룹장을 직접 넘기는 버튼은 아직 없음(나중에 추가 예정)
