# 09. 그룹 정산 (최소 송금)

그룹 내 모든 지출을 바탕으로 "누가 누구에게 얼마를 보내야 하는지"를 최소 건수의 송금으로 계산해 보여주고, 내가 보낼 상대방 계좌번호를 빠르게 복사하는 화면.

- **담당자**:
- **상태**: 초안

## 1. 화면 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | 09_group_settle |
| 역할 | 최소 송금 계산 결과 조회 + 계좌번호 복사 |
| 진입 경로 | 그룹 내부 하단 탭바 "정산" 탭 |
| 같은 그룹 내 탭 전환 | 08 지출 / 10 요약 |
| 다음 화면 | 없음 (화면 전환 없이 같은 화면에서 복사 액션만 발생) |

## 2. 진입 조건

- 08 §2와 동일한 그룹 멤버 조건

## 3. UI 구성

### 3.1 헤더

- 08 §3.1과 동일(08/09/10 공용)

### 3.2 하단 탭바 (그룹 내부 GNB)

- 08 §3.2와 동일(08/09/10 공용) — 현재 탭은 "정산"

### 3.3 안내 문구

- "가장 적은 횟수로 정산할 수 있도록 계산했어요. 내가 보낼 계좌는 탭하면 복사돼요. 지출을 등록하면 정산 결과도 실시간으로 바로 반영돼요."
- 지출을 추가/수정/삭제할 때마다 실시간 재계산
- 별도의 "정산 확정" 이벤트나 알림 없음

### 3.4 송금 목록

- 정렬: 내가 보낼 송금을 금액 내림차순으로 맨 위에 배치 → 그 외(다른 사람 간 송금)는 이름순으로 뒤에 나열
- 송금 행: 보내는 사람 → 받는 사람, 금액
- 내가 보낼 항목에만 추가로 노출: 받는 사람 은행·계좌, "탭해서 계좌번호 복사" 힌트(자세한 동작은 §4 참고)
- 다른 사람 간 송금은 계좌 정보를 아예 렌더링하지 않음(복사할 필요가 없으므로)

## 4. 기능

| 기능 | 동작 |
|---|---|
| 계좌 영역 탭 | 클립보드 복사 + 토스트("계좌번호가 복사되었습니다") + 해당 행 배경 잠깐 강조 |
| 헤더 back | 08 §4와 동일 — 항상 03 그룹 목록으로 이동 |

## 5. 데이터

- 화면에 보이는 송금 목록(누가 누구에게 얼마 보낼지)은 각 멤버의 잔액을 계산해서 만들어짐 — 잔액 계산법과 매칭 방식은 PLAN 문서 §정산 알고리즘 참고
- 잔액을 계산하려면 "각자 이 지출에서 얼마를 부담했는지"가 필요한데, 이 값은 지출을 등록할 때(11에서) 이미 정해진 걸 그대로 가져와 씀
- `users`: 송금 행에 표시할 이름
- `bank_accounts`: 받는 사람의 계좌 정보(은행명, 계좌번호) 표시용. 유저당 계좌는 1개뿐. "대기 중" 멤버는 계좌 자체가 없어 미등록 처리(§6 참고)

## 6. 예외 처리

| 상황 | 처리 |
|---|---|
| 지출이 아직 1건도 없음 | 송금 계산 자체를 하지 않고 "아직 등록된 지출이 없어요." 빈 상태 노출 |
| 지출은 있지만 전원 잔액이 0 (예: 번갈아 결제해서 각자 낸 돈과 부담할 돈이 정확히 같아진 경우) | 보내는 사람/받는 사람이 아예 없음(송금 행 자체가 0건) — 그 자리에 체크(✓) 아이콘 + "정산할 금액이 없어요. 모두 정확히 나눠 냈어요." 노출. 지출이 아예 없는 위 케이스와 달리 완료를 긍정적으로 알려주는 느낌으로 구분 |
| 받는 사람이 앱 미가입 "대기 중" 멤버(12에서 이름만으로 추가됨)라 계좌 정보가 없음 — 결제자로 지정된 지출이 있으면 정산에서 받을 사람이 될 수 있어 실제로 발생 가능 | "계좌 미등록 — {이름}님에게 직접 확인해주세요" 방어 문구, 복사 UI 비활성화 |
