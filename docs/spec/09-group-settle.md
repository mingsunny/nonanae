# 09. 그룹 정산 (최소 송금)

그룹 내 모든 지출을 바탕으로 "누가 누구에게 얼마를 보내야 하는지"를 최소 건수의 송금으로 계산해 보여주고, 내가 보낼 상대방 계좌번호를 빠르게 복사하는 화면.

- **담당자**:
- **상태**: 초안

## 1. 화면 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | 09_group_settle |
| 역할 | 최소 송금 계산 결과 조회 + 계좌번호 복사 |
| 진입 경로 | 그룹 내부 하단 탭바 "정산" 탭 |

## 2. 진입 조건

- 08 §2와 동일한 그룹 멤버 조건

## 3. UI 구성

### 3.1 헤더

- 08 §3.1과 동일(08/09/10 공용)

### 3.2 하단 탭바 (그룹 내부 GNB)

- 08 §3.2와 동일(08/09/10 공용) — 현재 탭은 "정산"

### 3.3 안내 문구

- "가장 적은 횟수로 정산할 수 있도록 계산했어요. 내가 보낼 계좌는 길게 누르면 복사돼요. 지출을 등록하면 정산 결과도 실시간으로 바로 반영돼요."
- 지출을 추가/수정/삭제할 때마다 실시간 재계산
- 별도의 "정산 확정" 이벤트나 알림 없음

### 3.4 송금 목록

- 정렬: 내가 보낼 송금을 금액 내림차순으로 맨 위에 배치 → 그 외(다른 사람 간 송금)는 이름순으로 뒤에 나열
- 내가 보낼 송금이 2건 이상이면 맨 위에 "내가 보낼 돈 · 총 N건 ₩X" 요약 라인 표시
  - 예: 내가 15만원을 갚아야 하는데, 가장 크게 받을 사람 A가 10만원, 그다음 B가 5만원 받을 상황이면 → 최소송금 계산상 나는 A에게 10만원 + B에게 5만원, 총 2건을 각각 보내야 함 → "내가 보낼 돈 · 총 2건 ₩150,000"
- 송금 행: 보내는 사람 → 받는 사람, 금액
- 내가 보낼 항목에만 추가로 노출: 받는 사람 은행·계좌, "길게 눌러 계좌번호 복사" 힌트, 롱프레스 진행 바(자세한 동작은 §4 참고)
- 다른 사람 간 송금은 계좌 정보를 아예 렌더링하지 않음

### 3.5 빈 상태

| 조건 | 문구 |
|---|---|
| 지출 자체가 0건 | "아직 등록된 지출이 없어요." |
| 지출은 있지만 전원 잔액이 0 | "정산할 금액이 없어요. 모두 정확히 나눠 냈어요." |

## 4. 기능

| 기능 | 동작 |
|---|---|
| 계좌 영역을 550ms 이상 길게 누름 | 클립보드 복사 + 토스트("계좌번호가 복사되었습니다") + 해당 행 배경 잠깐 강조 |
| 550ms 되기 전에 손을 떼거나(mouseup/leave) 터치를 취소함(touchend) | 복사는 실행되지 않고 진행 바만 원상태로 초기화 (이미 된 복사를 되돌리는 게 아니라, 실행 전 타이머를 취소하는 것) |
| 헤더 back | 08 §4와 동일 — 항상 03 그룹 목록으로 이동 |

## 5. 데이터

- 지출 1건 안에서 참여자별 분담액이 어떻게 정해지는지(균등 나머지 배분, 비율/금액 반올림 처리)는 11에서 등록 시점에 이미 계산·확정됨 — 09는 그 결과값을 사람별로 합산만 함(11 §데이터 참고)
- 멤버별 balance(잔액), paid(결제 합): 08의 모든 지출을 훑어서 사람별로 "결제한 금액 합"과 "부담한 분담액 합"을 각각 더한 뒤, `balance = 결제 합 − 부담 합`으로 계산
- 최소 송금 트랜잭션: `[{from, to, amount}]` — 채권자·채무자를 각각 금액 내림차순 정렬 후 가장 큰 채권자·채무자를 그리디 매칭(진짜 최소 거래 수를 보장하진 않지만, 여행 그룹 규모에서는 충분히 적은 건수가 나옴)
- 절대값 0.5 미만인 잔액/거래는 부동소수점 오차로 간주해 정산 대상에서 제외(여러 지출의 분담액을 더하는 과정에서 생길 수 있는 계산 오차 방어용)

## 6. 예외 처리

| 상황 | 처리 |
|---|---|
| 지출이 아직 1건도 없음 | 송금 계산 자체를 하지 않고 빈 상태 노출(§3.5) |
| 지출은 있지만 전원 잔액이 0 | 송금 대상이 없어 빈 상태 노출(§3.5) |
| 받는 사람이 앱 미가입 "대기 중" 멤버(12에서 이름만으로 추가됨)라 계좌 정보가 없음 — 결제자로 지정된 지출이 있으면 정산에서 받을 사람이 될 수 있어 실제로 발생 가능 | "계좌 미등록 — {이름}님에게 직접 확인해주세요" 방어 문구, 복사 UI 비활성화 |
