# 09. 그룹 정산 (최소 송금)

그룹 내 모든 지출을 바탕으로 "누가 누구에게 얼마를 보내야 하는지"를 최소 건수의 송금으로 계산해 보여주고, 내가 보낼 상대방 계좌번호를 빠르게 복사하는 화면.

- **담당자**:
- **상태**: 초안

## 1. 화면 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | 09_group_settle |
| 역할 | 최소 송금 계산 결과 조회 + 계좌번호 복사 |
| 진입 경로 | 그룹 내부 하단 탭바 "정산" 탭 |
| 같은 그룹 내 탭 전환 | 08 지출, 10 요약 |
| 다음 화면 | 없음 (화면 전환 없이 같은 화면에서 복사 액션만 발생) |

## 2. 진입 조건

- 08 §2와 동일한 그룹 멤버 조건
- 지출이 1건 이상 등록되어 있어야 실제 송금 목록이 계산됨(0건이면 빈 상태)

## 3. UI 구성

### 3.1 헤더

- 08 §3.1과 동일(08/09/10 공용)

### 3.2 하단 탭바 (그룹 내부 GNB)

- 08 §3.2와 동일(08/09/10 공용) — 현재 탭은 "정산"

### 3.3 안내 문구

- "가장 적은 횟수로 정산할 수 있도록 계산했어요. 내가 보낼 계좌는 길게 누르면 복사돼요. 지출을 등록하면 정산 결과도 실시간으로 바로 반영돼요."
- 지출을 추가/수정/삭제할 때마다 실시간 재계산 — 별도의 "정산 확정" 이벤트나 알림 없음

### 3.4 송금 목록

- 정렬: 내가 보낼 송금을 금액 내림차순으로 맨 위에 배치 → 그 외(다른 사람 간 송금)는 이름순으로 뒤에 나열
- 내가 보낼 송금이 2건 이상이면 맨 위에 "내가 보낼 돈 · 총 N건 ₩X" 요약 라인 표시
- 송금 행: 보내는 사람 → 받는 사람, 금액
- 내가 보낼 항목에만 추가로 노출: 받는 사람 은행·계좌, "길게 눌러 계좌번호 복사" 힌트, 롱프레스 진행 바
- 다른 사람 간 송금은 계좌 정보를 아예 렌더링하지 않음(복사할 필요가 없으므로)

### 3.5 계좌번호 롱프레스 복사

- 계좌 영역을 550ms 이상 길게 누르면 클립보드 복사 + 토스트("계좌번호가 복사되었습니다") + 해당 행 배경 잠깐 강조
- 누르는 동안 하단 바(press-bar)가 진행률을 시각화
- 누르는 도중 손을 떼거나(mouseup/leave) 터치를 취소하면(touchend) 복사되지 않고 진행 바만 초기화

### 3.6 빈 상태

| 조건 | 문구 |
|---|---|
| 지출 자체가 0건 | "아직 등록된 지출이 없어요." |
| 지출은 있지만 전원 잔액이 0 | "정산할 금액이 없어요. 모두 정확히 나눠 냈어요." |

## 4. 기능

| 기능 | 동작 |
|---|---|
| 계좌 영역 롱프레스(550ms↑) | 클립보드 복사 + 토스트 + 행 강조 |
| 롱프레스 중 손 떼기/취소 | 복사 취소, 진행 바 초기화 |
| 지출 추가/수정/삭제(11에서) | 정산 목록 실시간 재계산 |
| 헤더 back | 08 §4와 동일 — 항상 03 그룹 목록으로 이동 |

## 5. 데이터

- `expenses`: 08과 동일한 데이터를 그대로 사용해 잔액 계산
- 멤버별 balance(잔액), paid(결제 합)
- 나머지(잔돈) 배분 규칙(균등 분배에만 적용): 결제자가 반올림 때문에 손해 보지 않도록, 나머지는 결제자를 제외한 참여자 중 id 오름차순 앞쪽부터 1원씩 배분
- 최소 송금 트랜잭션: `[{from, to, amount}]` — 채권자·채무자를 각각 금액 내림차순 정렬 후 가장 큰 채권자·채무자를 그리디 매칭(진짜 최소 거래 수를 보장하진 않지만, 여행 그룹 규모에서는 충분히 적은 건수가 나옴)
- 절대값 0.5 미만인 잔액/거래는 부동소수점 오차로 간주해 정산 대상에서 제외

## 6. 예외 처리

빈 상태(지출 0건/잔액 0)는 3.6 참고. 그 외 이상 케이스만 정리:

| 상황 | 처리 |
|---|---|
| 받는 사람 계좌 정보가 비어 있음 (가입 시 필수라 정상 흐름에서는 발생 안 함) | "계좌 미등록 — {이름}님에게 직접 확인해주세요" 방어 문구, 복사 UI 비활성화 |
