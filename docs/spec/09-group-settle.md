# 09. 그룹 정산 (최소 송금)

그룹 내 모든 지출을 바탕으로 "누가 누구에게 얼마를 보내야 하는지"를 최소 건수의 송금으로 계산해 보여주고, 내가 보낼 상대방 계좌번호를 빠르게 복사하는 화면.

- **상태**: 초안

| 항목 | 내용 |

## 3. UI 구성

### 3.1 헤더

- 08 §3.1과 동일(08/09/10 공용)

### 3.2 하단 탭바 (그룹 내부 GNB)

- 08 §3.2와 동일(08/09/10 공용) — 현재 탭은 "정산"

### 3.3 안내 문구

- "가장 적은 횟수로 정산할 수 있도록 계산했어요. 내가 보낼 계좌는 탭하면 복사돼요. 지출을 등록하면 정산 결과도 실시간으로 바로 반영돼요."
- 지출을 추가/수정/삭제할 때마다 실시간 재계산
- 별도의 "정산 확정" 이벤트나 알림 없음

### 3.4 송금 목록

- 정렬: 내가 보낼 송금을 금액 내림차순으로 맨 위에 배치 → 그 외(다른 사람 간 송금)는 이름순으로 뒤에 나열
- 송금 행: 보내는 사람 → 받는 사람, 금액
- 내가 보낼 항목에만 추가로 노출: 받는 사람 은행·계좌, "탭해서 계좌번호 복사" 힌트(자세한 동작은 §4 참고)
- 다른 사람 간 송금은 계좌 정보를 아예 렌더링하지 않음(복사할 필요가 없으므로)

## 5. 데이터

- 참여자별 분담액(균등 나머지 배분, 비율/금액 반올림 처리)은 11에서 등록 시점에 이미 정수(원 단위)로 계산·확정됨 — 09는 그 값을 사람별로 합산만 함(11 §데이터 참고). 모든 값이 정수라 합산 과정에서 반올림 오차가 생기지 않음
- 멤버별 balance(잔액) — 화면에 이 숫자 자체가 보이는 건 아니고, 최소 송금 리스트를 계산하기 위해 내부적으로만 쓰는 값. "그 사람이 결제한 금액 합"에서 "그 사람이 참여자로서 부담해야 할 분담액 합"을 뺀 값
  - 예: A가 6만원짜리 저녁(A/B/C 균등, 각자 2만원 부담)을 결제하고, B가 2만원짜리 카페(A/B 균등, 각자 1만원 부담)를 결제했다면 → A는 6만 결제·3만 부담(2만+1만)이라 balance +3만(받을 돈), B는 2만 결제·3만 부담이라 balance −1만(보낼 돈), C는 0원 결제·2만 부담이라 balance −2만(보낼 돈). 세 사람 balance를 더하면 항상 0
  - 결제 금액(paid) 자체를 사람별로 보여주는 건 09가 아니라 10(요약)의 역할 — 10 §데이터 참고
- 최소 송금 트랜잭션 `[{from, to, amount}]`: "보낼 사람과 받을 사람을 최소 건수로 매칭해서 보여준다"는 요구사항만 정함 — 구체적인 매칭 순서/알고리즘은 아직 확정하지 않았고 구현 단계에서 결정(여행 그룹 규모에서 실무적으로 충분히 적은 건수가 나오면 됨, 이론적 최소 보장까지는 필요 없음)
- `users`: 송금 행에 표시할 보내는 사람/받는 사람 이름
- `bank_accounts`: 받는 사람의 기본 계좌(`is_primary=true`) 1개만 조회해서 은행명·계좌번호 표시 — 계좌를 여러 개 등록했어도 정산 화면엔 항상 기본 계좌만 노출(PLAN 스코프 결정 참고). "대기 중" 멤버는 이 테이블에 행 자체가 없어 계좌 미등록 처리(§6 참고)

## 6. 예외 처리

| 상황 | 처리 |
|---|---|
| 지출이 아직 1건도 없음 | 송금 계산 자체를 하지 않고 "아직 등록된 지출이 없어요." 빈 상태 노출 |
| 지출은 있지만 전원 잔액이 0 (예: 번갈아 결제해서 각자 낸 돈과 부담할 돈이 정확히 같아진 경우) | 체크(✓) 아이콘 + "정산할 금액이 없어요. 모두 정확히 나눠 냈어요." — 지출이 아예 없는 위 케이스와 달리 완료를 긍정적으로 알려주는 느낌으로 구분 |
| 받는 사람이 앱 미가입 "대기 중" 멤버(12에서 이름만으로 추가됨)라 계좌 정보가 없음 — 결제자로 지정된 지출이 있으면 정산에서 받을 사람이 될 수 있어 실제로 발생 가능 | "계좌 미등록 — {이름}님에게 직접 확인해주세요" 방어 문구, 복사 UI 비활성화 |
