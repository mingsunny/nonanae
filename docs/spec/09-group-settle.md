# 09. 그룹 정산 (최소 송금)

### 3.2 하단 탭바 (그룹 내부 GNB)

- 08 §3.2와 동일(08/09/10 공용)

### 3.3 안내 문구

- "가장 적은 횟수로 정산할 수 있도록 계산했어요. 내가 보낼 계좌는 탭하면 복사돼요. 지출을 등록하면 정산 결과도 실시간으로 바로 반영돼요."
- 지출을 추가/수정/삭제할 때마다 실시간 재계산
- 별도의 "정산 확정" 이벤트나 알림 없음

### 3.4 송금 목록

- 정렬
  - 내가 보낼 송금을 금액 내림차순으로 맨 위에 배치
  - 그 외(다른 사람 간 송금)는 이름순으로 뒤에 나열
- 송금 행: 보내는 사람 → 받는 사람, 금액
- 내가 보낼 항목에만 추가로 노출: 받는 사람 은행·계좌
  - "탭해서 계좌번호 복사" 힌트(자세한 동작은 §4 참고)
  - 다른 사람 간 송금은 계좌 정보를 아예 렌더링하지 않음(복사할 필요가 없으므로)

## 4. 기능

| 기능 | 동작 |
|---|---|
| 계좌 영역 탭 | 클립보드 복사 + 토스트("계좌번호가 복사되었습니다") + 해당 행 배경 잠깐 강조 |
| 헤더 back | 08 §4와 동일, 항상 03 그룹 목록으로 이동 |

## 5. 데이터

- 송금 행에 표시할 이름: schema.md의 이름 결정 순서 참고(대기중=Member.name / 게스트=Member.nickname / 정식회원=User.name)
- 받는 사람 계좌 정보(은행명, 계좌번호): `User.bank`/`User.account`
  - 유저당 계좌는 1개뿐(별도 엔티티 아님)
  - "대기 중" 멤버와 게스트는 `bank`/`account`가 null이라 계좌 미노출 처리(§6 참고)
- 최소 송금 매칭 방식으로 잔액 계산(schema.md 계산 로직 참고)


## 6. 예외 처리

| 상황 | 처리 |
|---|---|
| 지출이 아직 1건도 없음 | 송금 계산 자체를 하지 않고 "아직 등록된 지출이 없어요." 빈 상태 노출 |
| 지출은 있지만 전원(그룹 멤버 전부) 잔액이 0 (예: 번갈아 결제해서 각자 낸 돈과 부담할 돈이 정확히 같아진 경우) | 보내는 사람/받는 사람이 아예 없음(송금 행 자체가 0건). 그 자리에 체크(✓) 아이콘 + "정산할 금액이 없어요. 모두 정확히 나눠 냈어요." 노출. |
| 일부 멤버만 잔액이 0 (전원은 아님) | 잔액 0인 사람은 송금 목록에서 그냥 빠지고, 잔액이 남은 사람들끼리만 매칭되어 정상적으로 목록에 표시됨 |
| 받는 사람이 앱 미가입 "대기 중" 멤버 혹은 게스트 로그인 하여 계좌 정보가 없음  | "등록된 계좌가 없어요. {이름}님에게 직접 확인해주세요" 방어 문구, 복사 UI 비활성화 |
