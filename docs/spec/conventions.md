## 정식 회원 / 게스트 참가자

> 참가자가 정식 로그인(이메일) 없이도 서비스를 쓸 수 있게 하자는 결정에 따라 생긴 구분. 화면 스펙을 작성할 때 "이 화면은 누구를 대상으로 하는가"를 항상 먼저 확인할 것. 전체 배경과 흐름도는 [PLAN-sep03-yunjung.md](../../PLAN-sep03-yunjung.md) "결정된 질문 9" 및 "그룹 초대 흐름" 케이스 D/E 참고.
>
> ⚠️ **2026-09-12 업데이트**: 로그인 수단은 구글·카카오 연동이 제외되어 이메일+비밀번호 하나뿐. 아래 표의 "재입장 시 본인 확인(PIN)" 행은 sep10 프로토타입에 구현이 없어(이름만 입력하면 참여) 정식 결정인지 미확인 — [06-join-group.md](06-join-group.md) 참고.

| | 정식 회원 | 게스트 참가자 |
|---|---|---|
| 로그인 수단 | 이메일+비밀번호 | 없음 — 그룹 scope 세션 (재입장 인증 방식 미확인, 아래 참고) |
| 계좌정보 | 가입 시 필수 등록 | 없음 (등록 불가, 정식 전환 시에만 가능) |
| 세션 범위 | 전역 (여러 그룹을 하나의 계정으로 관리) | 그룹 하나에 한정 (다른 그룹엔 자동 로그인 안 됨) |
| 그룹장이 될 수 있는가 | 가능 | 불가 — 그룹장은 항상 정식 회원 |
| "내 그룹 목록"(홈 탭) 접근 | 가능 | 불가 — 초대코드로 참여하면 바로 그 그룹 내부로 진입 |
| 재입장 시 본인 확인 | 정식 로그인 자체가 본인 확인 (이메일+비밀번호) | (기존 결정) PIN 검증 5회 실패 시 15분 잠금 / (sep10 코드) 별도 인증 없음 — 미확인, [06-join-group.md](06-join-group.md) 참고 |
| 정산 화면에서 "돈 받는 입장"일 때 | 계좌번호 노출 | "계좌 미등록" 방어 문구로 대체, 복사 UI 비활성화 |

**관련 개념 — placeholder 멤버**: 그룹장이 [12-group-invite.md](12-group-invite.md)에서 "앱 미가입 친구를 이름만으로" 미리 추가해두는 멤버는 위 표의 "정식 회원"도 "게스트 참가자"도 아직 아닌 임시 상태. 나중에 그 사람이 실제로 초대코드를 사용하면 정식 회원 또는 게스트 둘 중 하나로 [07-join-match.md](07-join-match.md)에서 매칭·이관된다.

**이 결정이 영향을 주는 화면**: [01-login.md](01-login.md), [02-onboarding.md](02-onboarding.md), [03-group-list.md](03-group-list.md), [04-profile.md](04-profile.md), [06-join-group.md](06-join-group.md), [07-join-match.md](07-join-match.md), [09-group-settle.md](09-group-settle.md), [12-group-invite.md](12-group-invite.md). 새 화면을 스펙 문서로 작성할 때 참가자가 관여하는 화면이라면 이 목록에 추가하고 위 표를 기준으로 게스트 분기를 검토할 것.

## 용어집

- **정식 회원**: 이메일로 가입한 사용자. 계좌정보 등록 필수, 여러 그룹을 하나의 계정으로 관리 가능. 자세한 내용은 [정식 회원 / 게스트 참가자](#정식-회원--게스트-참가자) 참고
- **게스트 참가자**: 정식 로그인 없이 닉네임+PIN만으로 그룹 하나에 참여하는 사용자. 계좌정보 없음
- **경량 세션**: 게스트 참가자가 발급받는, 특정 그룹 하나에만 유효한 세션(정식 로그인 세션과 구분하기 위한 용어)
- **PIN**: 게스트 참가자가 재입장(기기 변경 등) 시 본인 확인에 쓰는 4자리 숫자. 비밀번호가 아니라 최소 인증 수단
- **placeholder 멤버**: 그룹장이 [12-group-invite.md](12-group-invite.md)에서 이름만으로 미리 추가해둔, 아직 실제로 참여하지 않은 멤버
