## 정식 회원 / 게스트 참가자

> 참가자가 정식 로그인(이메일) 없이도 서비스를 쓸 수 있게 하자는 결정에 따라 생긴 구분. 화면 스펙을 작성할 때 "이 화면은 누구를 대상으로 하는가"를 항상 먼저 확인할 것. 전체 배경과 흐름도는 [PLAN-sep03-yunjung.md](../../PLAN-sep03-yunjung.md) "결정된 질문 9" 및 "그룹 초대 흐름" 케이스 D/E 참고.
>
> ✅ **2026-09-12 확정 (sep10 프로토타입 기준)**: 로그인 수단은 구글·카카오 연동이 제외되어 이메일+비밀번호 하나뿐. **게스트의 닉네임+PIN 재입장 인증도 스펙에서 제외** — 게스트는 `User` 계정 자체를 만들지 않고, 그룹 멤버 목록에서 이름만으로 참여/재참여한다(스푸핑 방지 장치 없음 — 마찰을 줄이기 위해 수용한 트레이드오프). 자세한 흐름은 [06-join-group.md](06-join-group.md) 참고.

| | 정식 회원 | 게스트 참가자 |
|---|---|---|
| 로그인 수단 | 이메일+비밀번호 | 없음 — 초대코드로 그룹에 이름만 입력해 참여 |
| 계좌정보 | 가입 시 필수 등록 | 없음 (등록 불가, 정식 전환 시에만 가능) |
| 세션 범위 | 전역 (여러 그룹을 하나의 계정으로 관리) | 그룹 하나에 한정 (다른 그룹엔 자동 로그인 안 됨) |
| 그룹장이 될 수 있는가 | 가능 | 불가 — 그룹장은 항상 정식 회원 |
| "내 그룹 목록"(홈 탭) 접근 | 가능 | 불가 — 초대코드로 참여하면 바로 그 그룹 내부로 진입 |
| 재입장 시 본인 확인 | 정식 로그인 자체가 본인 확인 (이메일+비밀번호) | 없음 — 그룹 멤버 목록에서 같은 이름을 다시 고르면 그 자리로 인식됨 |
| 정산 화면에서 "돈 받는 입장"일 때 | 계좌번호 노출 | "계좌 미등록" 방어 문구로 대체, 복사 UI 비활성화 |

**관련 개념 — placeholder 멤버**: 그룹장이 [12-group-invite.md](12-group-invite.md)에서 "앱 미가입 친구를 이름만으로" 미리 추가해두는 멤버는, 데이터 구조상 게스트와 동일함(`Member.userId`가 null, `Member.name`만 있음). 실제로 그 사람이 초대코드를 써서 들어오면 정식 회원으로 전환(`userId` 채움)되거나, 로그인 없이 그대로 게스트로 남는다 — [07-join-match.md](07-join-match.md)에서 처리.

**이 결정이 영향을 주는 화면**: [01-login.md](01-login.md), [02-onboarding.md](02-onboarding.md), [03-group-list.md](03-group-list.md), [04-profile.md](04-profile.md), [06-join-group.md](06-join-group.md), [07-join-match.md](07-join-match.md), [09-group-settle.md](09-group-settle.md), [12-group-invite.md](12-group-invite.md). 새 화면을 스펙 문서로 작성할 때 참가자가 관여하는 화면이라면 이 목록에 추가하고 위 표를 기준으로 게스트 분기를 검토할 것.

## URL 경로 (라우팅)

> 2026-09-20 확정. React(Vite) 구현 시 화면 간 이동의 기준이 되는 경로. 화면을 나눠 맡은 두 담당자(01~07·14 / 08~13)가 서로의 화면으로 넘어가는 지점에서 어긋나지 않도록 미리 고정함. 라우터는 React Router 사용.

| 화면 | 경로 | 비고 |
|---|---|---|
| 01 로그인 / 회원가입 | `/login` | |
| 03 그룹 목록 (홈 탭) | `/groups` | 13 알림 오버레이가 이 화면 위에서 열림 |
| 04 프로필 (탭) | `/profile` | |
| 05 새 그룹 만들기 | `/groups/new` | 생성 직후 08로 이동 |
| 06 초대코드로 참여 / 07 멤버 매칭 | `/join` | 카카오톡 공유 링크는 `/join?code=ABCDEF`, 개인화 초대 링크는 `/join?code=ABCDEF-{memberId}` ([12](12-group-invite.md) 참고). 06→07은 같은 경로 안의 단계 전환 |
| 14 비밀번호 재설정 | `/password-reset` | |
| 08 그룹 지출 내역 | `/groups/:groupId/expenses` | 그룹 내부 기본 탭. `/groups/:groupId`로 들어오면 여기로 이동 |
| 09 그룹 정산 | `/groups/:groupId/settle` | |
| 10 그룹 요약 | `/groups/:groupId/summary` | |
| 11 지출 추가 | `/groups/:groupId/expenses/new` | 신규 등록 모드 |
| 11 지출 수정 | `/groups/:groupId/expenses/:expenseId` | 수정 모드 (기존 값 프리필) |
| 12 멤버 초대 | `/groups/:groupId/members` | 05에서 그룹을 만든 직후 이동해 올 땐 `navigate(path, { state: { fromCreation: true } })`로 넘기면 상단 back 버튼이 숨겨짐(하단 "그룹으로 가기"는 항상 표시) |
| 13 알림 | (경로 없음) | 03 위에 뜨는 전역 오버레이라 별도 URL을 갖지 않음 |

- 02 온보딩은 화면 존치 여부가 미정이라([handoff.md](handoff.md) 참고) 경로를 정하지 않음.
- 08/09/10은 하나의 그룹 레이아웃(공용 헤더 + 하단 탭바) 안에서 콘텐츠만 바뀌는 중첩 경로.

## 용어집

- **정식 회원**: 이메일로 가입한 사용자. 계좌정보 등록 필수, 여러 그룹을 하나의 계정으로 관리 가능. 자세한 내용은 [정식 회원 / 게스트 참가자](#정식-회원--게스트-참가자) 참고
- **게스트 참가자**: 정식 로그인 없이 이름만으로 그룹 하나에 참여하는 사용자. 계좌정보 없음, 별도 계정(User)도 없음. 재입장 시 별도 인증 없음(2026-09-12 확정)
- **placeholder 멤버**: 그룹장이 [12-group-invite.md](12-group-invite.md)에서 이름만으로 미리 추가해둔, 아직 실제로 참여하지 않은 멤버. 데이터 구조상 게스트와 동일(`Member.userId`가 null)
