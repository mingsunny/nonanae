# 11. 지출 추가 / 수정 폼

> "나누기 방식(균등/비율/금액)" 옵션이 추가됨. 기존 지출을 편집할 때도 같은 화면을 재사용하며(제목/삭제 버튼 노출로 구분), 이 경우의 예외처리도 함께 다뤄야 함.

지출 1건을 등록하거나 기존 지출을 수정하는 입력 폼. 그룹 내 정산·요약 계산의 원천 데이터가 여기서 만들어진다.

- **상태**: 초안

## 1. 화면 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | 11_expense_form |
| 역할 | 지출 신규 등록 / 기존 지출 수정 (같은 화면 재사용) |
| 진입 경로 | 08의 FAB(＋) → 신규 등록 모드 / 08의 지출 카드 탭 → 수정 모드 |
| 다음 화면 | 제출/수정/삭제 후 08(지출 탭)로 복귀 |

## 2. 진입 조건

- 08 §2와 동일한 그룹 멤버 조건

## 3. UI 구성

### 3.1 입력 필드

- 사용 금액(숫자)
- 항목명(텍스트)
- 사용 날짜(날짜 선택): 기본값 오늘
  - 사용 날짜는 08의 날짜 그룹핑 기준(`spent_at`)이 됨(08 §3.3 참고)
- 카테고리 칩(6개 중 단일 선택)
- 영수증 사진 업로드(선택)
  - 사진 첨부 시 미리보기 노출
- 결제자: 기본 값 등록자

### 3.2 나누기 방식 & 참여자

- 나누기 방식 토글: 균등 / 비율(%) / 금액(원)
- 참여자 체크박스: 그룹 멤버 중 일부만 선택 가능, 기본값 전원 선택. 체크된 사람 옆에 분담액이 항상 표시
  - 균등: 분담액은 읽기 전용으로 자동 계산되어 표시. 나머지 1원은 참여자 순서로만 배분(결제자 예외 없음 — 결제자를 바꿔도 분담액은 안 바뀜, §5 참고)
  - 비율·금액: 분담액을 인라인 입력 필드로 직접 입력. 모드 전환/참여자 변경 시 균등 배분값으로 먼저 채워주고(prefill), 필요한 부분만 고쳐 쓰면 됨
- 비율/금액 모드에서는 합계가 목표값(비율=100%, 금액=총액)과 일치하는지 실시간 검증 문구 노출(일치 시 teal, 불일치 시 brick)

### 3.3 하단 액션

- 제출 버튼: "지출 등록하기"(신규) / "저장하기"(수정), 조건 미충족 시 비활성
- "이 지출 삭제하기" 링크: 수정 모드에서만 노출

## 4. 기능

| 기능 | 동작 |
|---|---|
| 카테고리 칩 선택 | 선택 상태 갱신 |
| 결제자 변경 | 참여자별 분담액에는 영향 없음(나머지 1원 배분은 참여자 순서로만 정해지고 결제자 예외 없음) — 09/10에서 결제 합계(paid) 집계 대상만 바뀜 |
| 나누기 방식 전환(균등→비율/금액) | 현재 참여자 기준 균등 배분값으로 프리필 |
| 참여자 체크/해제 | 분담액 재계산, 비율/금액 모드면 프리필도 다시 실행 |
| 참여자별 분담액 직접 입력 | 합계 검증 + 제출 버튼 활성화 여부 갱신 |
| 영수증 사진 첨부 | 미리보기 표시, 업로드 라벨 문구 변경 |
| "지출 등록하기"/"저장하기" | 08·09·10 실시간 재계산, 신규 등록 시에만 알림(13) 생성(수정은 알림 생성 안 함), 08(지출 탭)로 복귀 |
| "이 지출 삭제하기" | 확인 다이얼로그 → 삭제, 08(지출 탭)로 복귀 |
| 헤더 back | 08(지출 탭)로 복귀(입력 중인 내용 저장 안 함) |

## 5. 데이터

- **결제자 목록**: 이 그룹의 멤버 전원(정식 가입 + 대기 중 + 게스트) 노출
  - 결제자 저장 시 `expenses.paid_by`
- **참여자 목록**: 그룹 멤버 중 일부/전체 선택 → 저장되면 `expense_participants`에 한 명당 한 행씩
- **금액 분담 로직**: 균등/비율/금액 중 선택한 방식으로 참여자별 몫을 정함 → 확정된 몫이 `expense_participants.share_amount`로 저장(균등은 매번 계산이라 저장 안 함)
  - 균등: 나머지 1원은 참여자를 정해진 순서로 돌면서 배분(결제자 예외 없음)
  - 비율: % → 원 환산 시 남는 오차를 같은 방식으로 배분
  - 금액: 입력값 그대로 반올림
- **09/10에서 쓰이는 방식**: 결제자는 09/10의 "결제 합(paid)" 집계 대상이 되고, 참여자별 분담액은 09/10의 "부담 합"에 더해짐 — 이 둘의 차이(`결제 합 − 부담 합`)가 잔액(balance)이 되어 정산·요약 계산의 재료로 쓰임(09 §5, 10 §5 참고)
- 그 외 저장 필드: `expenses`에 title, amount, category, receipt_image_url, split_type, spent_at(사용 날짜, 기본값 오늘·수정 가능) — ⚠️ PLAN 갭: `title`은 PLAN 스키마에 없고 `memo`(선택적 메모)만 있음(08 §5 참고)

## 6. 예외 처리

| 상황 | 처리 |
|---|---|
| 제출 조건 미충족(금액>0, 항목명 입력, 참여자 1명 이상, 비율/금액 모드면 합계 일치) | 제출 버튼 비활성화 |
| 참여자를 마지막 1명까지 해제하려는 시도 | 막고 토스트("최소 1명은 선택되어야 해요") |
| 영수증 사진 업로드 실패/용량 초과 | 에러 토스트로 안내, 업로드 박스는 그대로 유지되어 바로 재시도 가능. 사진은 원래 선택 사항이라 재시도 없이 제출하면 사진 없이 등록됨(제출 자체를 막지 않음) — 프로토타입엔 실패 케이스 자체가 구현되어 있지 않음 |
