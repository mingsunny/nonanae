# 06. 초대코드로 참여

> 초대코드 입력 화면(`screen-join-lookup`). 코드 종류·로그인 여부·재입장 여부에 따라 그룹으로 바로 이동하거나, 사전 등록된 멤버와 매칭하는 화면([07-join-match.md](07-join-match.md))으로 이동함 — 자세한 분기는 아래 "액션 & 결과" 참고.

> ⚠️ **이 화면을 작성할 담당자는 반드시 확인**: 참가자는 정식 로그인 없이도 참여할 수 있도록 결정됨. "로그인하고 참여"는 [01-login.md](01-login.md)의 이메일 회원가입/로그인 폼을 재사용함(**구글·카카오 연동은 스펙에서 제외됨**, 2026-09-12). 계좌정보는 로그인 없이 참여하는 참가자(게스트)에게 요구하지 않음. 관련 화면: [conventions.md](conventions.md#정식-회원--게스트-참가자).
>
> ✅ **게스트 재입장 인증 확정 (2026-09-12, sep10 프로토타입 기준)**: 닉네임+PIN 재입장 인증(5회 실패 시 잠금)은 스펙에서 제외됨. 게스트는 `User` 계정을 만들지 않고, 그룹 멤버 목록에서 이름만으로 참여/재참여함(재입장 시 같은 이름을 다시 고르면 그 자리로 인식되며 별도 인증 없음 — 스푸핑 방지 장치 없이 마찰을 줄이는 쪽을 택한 트레이드오프).
>
> **sep10 기준 실제 화면 구조**(작성 시 반영할 것): `screen-join-group` 단일 화면이 아니라 2단계로 나뉨.
> 1. **초대코드 입력** (`screen-join-lookup`): 코드 형식은 공용 코드(`ABCDEF`) 또는 특정 대기 중 멤버를 지정한 개인화 코드(`ABCDEF-memberId`, [12-group-invite.md](12-group-invite.md) 참고) 두 가지. 개인화 코드면 아래 2번 화면 없이 바로 그 멤버로 매칭됨
> 2. **참여하기** (`screen-join-pick`): 공용 코드인 경우 그룹 멤버 목록에서 "본인이 누구인지" 고르거나(이미 `userId`가 있는 멤버는 선택 불가 — 본인 계정으로 로그인해야 함), 목록에 없으면 로그인 여부에 따라 (로그인 안 함) 이름 입력 후 새로 참여 / (로그인함) 그대로 새 멤버로 추가

- **담당자**: 민선
- **상태**: 작성중

## 목적

친구에게 받은 초대코드를 입력해 정산 그룹을 찾는, 초대 참여 흐름의 시작 화면. 로그인 여부와 무관하게 동일한 화면을 쓰는 공용 진입점이다.

## 주요 기능

- 초대코드 입력 (4자 이상이면 "다음" 버튼 활성화)
- 코드 형식 자동 구분: 공용 코드(6자리) vs 특정 멤버를 지정한 개인화 코드(`공용코드-멤버ID`)
- 코드 확인 결과에 따라 그룹으로 바로 이동 / 개인화 매칭 / [07-join-match.md](07-join-match.md)로 이동 자동 분기
- 뒤로가기: 로그인 상태면 그룹 목록(홈)으로, 비로그인 상태면 로그인 화면으로

## 진입 경로

- [01-login.md](01-login.md)의 "친구에게 받은 초대코드가 있어요" 링크 (비로그인 상태에서 진입)
- [03-group-list.md](03-group-list.md) 홈 탭의 "초대코드 입력" 버튼 (로그인 상태에서 진입)
- 두 경로 모두 같은 진입 함수를 공유하는 공용 화면

## UI 구성요소

- 상단바: 뒤로가기, 타이틀 "초대코드로 참여"
- 안내 문구: "친구에게 받은 초대코드를 입력해주세요."
- 초대코드 입력 필드 (`jl-code-input`, text, placeholder "예) 4B7K2P")
- 에러 메시지 영역 (`jl-error`, 기본 숨김, "일치하는 그룹을 찾을 수 없어요. 코드를 다시 확인해주세요.")
- "다음" 버튼 (`jl-next-btn`) — 입력값이 4자 미만이면 disabled

## 데이터

- `Group.inviteCode`로 그룹 조회. 입력값이 "코드-memberId" 형태면 개인화 코드로 파싱해 대상 `Member.id`를 함께 얻음
- 이미 이 그룹에 속해 있는지(재입장 여부)는 로그인 상태면 `Member.userId === currentUser.id`로, 비로그인 상태면 세션에 남아있는 `viewAsMemberId`로 판별
- 개인화 코드의 대상이 아직 매칭 안 된 placeholder(`userId`가 null)일 때만 자동 매칭 대상으로 인정

## 액션 & 결과

| 상황 | 결과 |
|---|---|
| 코드 입력/수정 | 4자 미만이면 "다음" 비활성화, 에러 메시지 숨김 |
| "다음" 클릭 — 존재하지 않는 코드 | 에러 메시지 노출, 화면 전환 없음 |
| "다음" 클릭 — 이미 이 그룹 멤버(재입장) | 안내 없이 곧바로 그룹 내부([08-group-expense-list.md](08-group-expense-list.md))로 이동 |
| "다음" 클릭 — 개인화 코드 + 대상 placeholder가 아직 미매칭 | 로그인 상태면 그 자리에 내 계정 매칭, 비로그인이면 그 자리로 세션 지정 → "{이름}님으로 참여했어요" 토스트 → 그룹 내부로 이동 ([07-join-match.md](07-join-match.md) 건너뜀) |
| "다음" 클릭 — 공용 코드 (또는 개인화 코드의 대상이 이미 매칭됨/존재하지 않음) | [07-join-match.md](07-join-match.md) "참여하기" 화면으로 이동 |
| 뒤로가기 | 로그인 상태면 [03-group-list.md](03-group-list.md) 홈 탭으로, 아니면 [01-login.md](01-login.md)로 |

## 예외처리

- 코드가 4자 미만이면 진행 자체가 불가
- 코드는 대소문자 구분 없이 대문자로 변환해 비교함
- 존재하지 않는 코드는 에러 메시지만 노출하고 화면은 유지됨 (다른 화면으로 튕기지 않음)
- 개인화 코드의 대상 멤버가 이미 다른 사람에 의해 매칭된 경우, 별도 안내 없이 공용 코드처럼 조용히 [07-join-match.md](07-join-match.md)로 넘어감 — "이미 다른 분이 참여하셨어요" 같은 명시적 피드백은 없음
- 이미 이 그룹 멤버인 상태(재입장)에서 코드를 다시 입력해도 "이미 참여 중입니다" 같은 안내 없이 그냥 그룹으로 이동함
- 게스트(로그인 없이 이름만으로 참여)는 재입장 시에도 별도 인증이 없어, 같은 그룹의 다른 사람이 그 이름을 알면 그 자리로 들어올 수 있음(스푸핑 위험 — 수용된 트레이드오프, [conventions.md](conventions.md#정식-회원--게스트-참가자) 참고)
