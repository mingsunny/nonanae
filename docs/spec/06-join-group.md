# 06. 초대코드로 참여

> 초대코드 입력 화면(`screen-join-lookup`). 코드 종류·로그인 여부·재입장 여부에 따라 그룹으로 바로 이동하거나, 사전 등록된 멤버와 매칭하는 화면([07-join-match.md](07-join-match.md))으로 이동함 — 자세한 분기는 아래 "액션 & 결과" 참고.

> ⚠️ **이 화면을 작성할 담당자는 반드시 확인**: 참가자는 정식 로그인 없이도 참여할 수 있도록 결정됨. "로그인하고 참여"는 [01-login.md](01-login.md)의 이메일 회원가입/로그인 폼을 재사용함(**구글·카카오 연동은 스펙에서 제외됨**, 2026-09-12). 계좌정보는 로그인 없이 참여하는 참가자(게스트)에게 요구하지 않음. 관련 화면: [conventions.md](conventions.md#정식-회원--게스트-참가자).
>
> ✅ **게스트 재입장 인증 확정 (2026-09-12, sep10 프로토타입 기준)**: 닉네임+PIN 재입장 인증(5회 실패 시 잠금)은 스펙에서 제외됨. 게스트는 `User` 계정을 만들지 않고, 그룹 멤버 목록에서 이름만으로 참여/재참여함(재입장 시 같은 이름을 다시 고르면 그 자리로 인식되며 별도 인증 없음 — 스푸핑 방지 장치 없이 마찰을 줄이는 쪽을 택한 트레이드오프).
>
> **sep10/sep19 기준 실제 화면 구조**(작성 시 반영할 것): `screen-join-group` 단일 화면이 아니라 2단계로 나뉨.
> 1. **초대코드 입력** (`screen-join-lookup`): 코드 형식은 공용 코드(`ABCDEF`) 또는 특정 대기 중 멤버를 지정한 개인화 코드(`ABCDEF-memberId`, [12-group-invite.md](12-group-invite.md) 참고) 두 가지. 개인화 코드면 아래 2번 화면 없이 바로 그 멤버로 매칭됨
> 2. **참여하기** (`screen-join-pick`): 공용 코드인 경우 그룹 멤버 목록에서 "본인이 누구인지" 고르거나(이미 `userId`가 있는 멤버는 선택 불가 — 본인 계정으로 로그인해야 함), 목록에 없으면 로그인 여부에 따라 (로그인 안 함) 이름 입력 후 새로 참여 / (로그인함) 그대로 새 멤버로 추가

> ✅ **그룹장 승인 갱신 (2026-10-17)** — 최신 기준은 아래 [유저 플로우](#유저-플로우-2026-10-17). 요약:
> - 처음 참여할 때는 그룹장에게 **참여 요청**을 보내고, 그룹장이 승인해야 멤버가 된다. 링크를 여는 것만으로는 요청하지 않고 "…님으로 참여하기"를 눌러야 요청한다.
> - 승인 없이 바로 들어가는 경우: (1) 이미 이 그룹 멤버인 계정·브라우저의 재입장 (2) **그룹장이 없는 그룹에 들어오는 정식 회원**(그룹장이 탈퇴했고 남은 정식 회원도 없음, [12](12-group-invite.md#그룹장-탈퇴-2026-10-17)). ※ 이미 승인된 게스트 자리의 개인 링크도 **승인이 필요**하다(2026-10-25 정정: 승인 없이 입장시키면 초대코드만 아는 사람이 자리를 가로챌 수 있음).
> - 요청 상태는 **승인 요청중 / 승인됨 / 거절됨** 세 가지. 요청 취소 버튼은 없앰.
> - "본인이 누구인지 골라주세요"(멤버 고르기) 화면은 모든 곳에서 삭제. 공용 코드로 오면 새 멤버로 참여한다([07](07-join-match.md)).
> - 게스트에게는 계좌번호를 보여주지 않는다([09](09-group-settle.md)).
>
> ~~✅ **그룹장 승인 (2026-10-11)**~~ (아래는 당시 기록): 초대코드로는 더 이상 바로 그룹에 들어가지 않는다. 로그인·회원가입·게스트·개인 초대 링크 모두 **참여 요청**만 보내고, 그룹장이 [12-group-invite.md](12-group-invite.md)에서 승인해야 멤버가 된다. 이미 그 그룹 멤버인 계정(게스트는 같은 브라우저 세션)의 재입장만 승인 없이 들어간다. 요청을 보내면 "승인 대기" 화면이 뜨고, 몇 초마다 확인해 승인되면 저절로 그룹으로 들어간다. 초대코드가 새어 나가도 낯선 사람이 지출·계좌를 보지 못하게 하려는 보안 결정.

- **담당자**: 민선
- **상태**: 작성중

## 목적

친구에게 받은 초대코드를 입력해 정산 그룹을 찾는, 초대 참여 흐름의 시작 화면. 로그인 여부와 무관하게 동일한 화면을 쓰는 공용 진입점이다.

## 유저 플로우 (2026-10-17)

### 1. 링크를 열었을 때 첫 화면

| 들어온 방법 | 상황 | 보이는 화면 |
|---|---|---|
| 아무 코드·링크 | 이미 이 그룹 멤버(같은 계정 또는 같은 브라우저의 게스트) | 안내 없이 바로 그룹([08](08-group-expense-list.md)) |
| 아무 코드·링크 | 이 그룹에 보낸 요청이 승인 대기 중 | **승인 요청중** 화면 (아래 2) |
| 아무 코드·링크 | 이 그룹에 보낸 요청이 거절됨 | **거절됨** 화면 (아래 2) |
| 개인 초대 링크 `코드-멤버ID` | 그 자리가 아직 계정에 연결되지 않음(대기 중 멤버, 또는 승인된 게스트 자리) | **초대 화면**: "초대받은 그룹" 카드(그룹 이름) + "{이름}님으로 참여하기" 큰 버튼. 비로그인이면 그 아래 "로그인" / "회원가입" 버튼 나란히. 로그인 상태면 {이름}은 내 계정 이름 |
| 개인 초대 링크 | 그 자리가 이미 회원 계정에 연결됨 + 비로그인 | "승인이 완료됐어요. 로그인하고 사용해요." 안내 + "로그인" 버튼 |
| 개인 초대 링크 | 그 자리가 이미 회원 계정에 연결됨 + 다른 계정으로 로그인 | 공용 코드와 같은 **그룹 초대 화면** |
| 공용 코드 / 공용 링크 | — | **그룹 초대 화면**([07](07-join-match.md)): 로그인 상태면 "{내 이름}님으로 참여하기", 비로그인이면 이름 입력 + "이 이름으로 참여하기" + "로그인" / "회원가입" |

### 2. 참여를 누른 뒤 — 요청 상태

| 상태 | 요청한 사람이 보는 화면 | 다음 |
|---|---|---|
| **승인 요청중** | 콜아웃 "[그룹명] 그룹장에게 참여를 요청했어요. 그룹장이 승인하면 바로 시작할 수 있어요." + "승인 요청중" 상태 표시 + "승인이 완료되면 같은 초대 링크로 그룹에 참여할 수 있어요". 로그인 상태면 "그룹 목록으로" 버튼(목록에 "그룹장 승인을 기다리고 있어요"로 보임). **요청 취소 버튼 없음** | 화면이 열려 있으면 5초마다 확인. 승인되면 "참여가 승인됐어요" 토스트 후 그룹으로. 거절되면 거절됨 화면으로 바뀜 |
| **승인됨** | 별도 화면 없음. 같은 초대 링크를 다시 열면 바로 그룹으로 | 요청한 사람에게 승인 알림은 가지 않음(게스트는 알림을 받을 곳이 없음) — 그래서 "같은 초대 링크로" 안내를 둠 |
| **거절됨** | 콜아웃 "[그룹명] 그룹장이 참여 요청을 거절했어요." + "거절됨" 상태 표시 + "그룹장에게 확인한 뒤 다시 요청해주세요." + "다시 요청하기" 버튼. 로그인 상태면 그룹 목록에도 "그룹장이 참여 요청을 거절했어요"로 보임 | "다시 요청하기" → 1의 초대 화면 / 그룹 초대 화면 → 다시 요청하면 승인 요청중이 되고 그룹장에게 다시 알림 |

### 3. 로그인·회원가입하고 참여

- 초대 화면·그룹 초대 화면의 "로그인" / "회원가입"을 누르면, 마친 뒤 **같은 초대 링크로 돌아온다**.
- 회원가입: 이메일·비밀번호([01](01-login.md)) → 이메일 확인 → 계좌 등록([02](02-onboarding.md)) → 초대 링크로 복귀. 개인 초대 링크로 왔으면 계좌 등록의 이름 칸에 **초대받은 이름이 미리 채워짐**. 바꾸면 바꾼 이름으로 "{이름}님으로 참여하기"가 보인다.
- 계좌 등록 화면에는 "나중에 하기(로그아웃)"가 없다.
- 회원도 처음 참여할 때는 그룹장 승인이 필요하다(예외: 위 콜아웃의 (2)·(3)).

### 4. 게스트(비회원)

- 같은 브라우저로 다시 들어오면 승인 없이 바로 그룹으로.
- 다른 기기·브라우저·시크릿 창은 새 사람으로 보인다. 개인 초대 링크로 와도 이미 승인된 자리를 이어받으려면 **방장 승인이 다시 필요하다**. 공용 코드로 오면 새 사람으로 다시 요청한다.
- 게스트는 정산 화면에서 **계좌번호를 볼 수 없다**. 그룹 화면 위 "계정으로 더 편리하게 이용하세요 · 로그인하거나 가입하면 계좌번호도 볼 수 있어요" 카드에서 로그인/회원가입하면, 내 자리의 개인 초대 링크로 돌아와 **승인 없이 그 자리가 계정에 연결**된다(지출·정산 기록 그대로).
- 트레이드오프: 개인 초대 링크만 있으면 그 게스트 자리로 들어올 수 있다. 그래서 게스트에게 계좌번호를 숨긴다.

### 5. 그룹장 쪽 (요약 — 자세히는 [12](12-group-invite.md))

- 요청이 오면: 그룹 목록 카드에 "참여 요청 N" 배지([03](03-group-list.md)), 그룹 화면 맨 위에 "{이름}님(외 N명)이 참여를 요청했어요 · 확인하기" 배너([08](08-group-expense-list.md)), 알림([13](13-notifications.md)).
- 멤버 화면([12](12-group-invite.md))에서 승인 / 거절. 그룹장에게는 승인 대기 중인 요청만 보인다.
- 그룹장이 탈퇴하면 남은 회원 중 가장 먼저 들어온 사람이 그룹장이 된다. 남은 정식 회원이 없으면 정식 회원만 승인 없이 바로 참여(게스트는 요청만 남김).

## 주요 기능

- 초대코드 입력 (4자 이상이면 "다음" 버튼 활성화)
- 코드 형식 자동 구분: 공용 코드(6자리) vs 특정 멤버를 지정한 개인화 코드(`공용코드-멤버ID`)
- 코드 확인 결과에 따라 그룹으로 바로 이동 / 개인화 매칭 / [07-join-match.md](07-join-match.md)로 이동 자동 분기
- 뒤로가기: 로그인 상태면 그룹 목록(홈)으로, 비로그인 상태면 인트로 화면으로

- "다음" 버튼 (`jl-next-btn`) — 입력값이 4자 미만이면 disabled

## 데이터

- `Group.inviteCode`로 그룹 조회. 입력값이 "코드-memberId" 형태면 개인화 코드로 파싱해 대상 `Member.id`를 함께 얻음
- 이미 이 그룹에 속해 있는지(재입장 여부)는 로그인 상태면 `Member.userId === currentUser.id`로, 비로그인 상태면 세션에 남아있는 `viewAsMemberId`로 판별
- 개인화 코드의 대상이 아직 매칭 안 된 placeholder(`userId`가 null)일 때만 자동 매칭 대상으로 인정

## 예외처리

- 코드가 4자 미만이면 진행 자체가 불가
- 코드는 대소문자 구분 없이 대문자로 변환해 비교함
- 존재하지 않는 코드는 에러 메시지만 노출하고 화면은 유지됨 (다른 화면으로 튕기지 않음)
- 개인화 코드의 대상 멤버가 이미 다른 사람에 의해 매칭된 경우, 별도 안내 없이 공용 코드처럼 조용히 [07-join-match.md](07-join-match.md)로 넘어감 — "이미 다른 분이 참여하셨어요" 같은 명시적 피드백은 없음
- 이미 이 그룹 멤버인 상태(재입장)에서 코드를 다시 입력해도 "이미 참여 중입니다" 같은 안내 없이 그냥 그룹으로 이동함
- ~~게스트는 재입장 시에도 별도 인증이 없어, 같은 그룹의 다른 사람이 그 이름을 알면 그 자리로 들어올 수 있음~~ (2026-10-17: 멤버 고르기 화면이 없어져 이름만으로는 남의 자리를 고를 수 없음. 대신 **승인된 게스트 자리의 개인 초대 링크**를 가진 사람은 승인 없이 그 자리로 들어올 수 있음 — 그래서 게스트에게 계좌번호를 숨김)
- 공용 코드로 들어온 사람은 항상 새 멤버로 참여하므로, 그룹장이 미리 추가해 둔 사람(대기 중 멤버)이 공용 코드로 들어오면 같은 사람이 두 자리로 나뉠 수 있음 — 미리 추가한 사람에게는 [12](12-group-invite.md)의 "초대 보내기"(개인 초대 링크)로 보내야 함
- 게스트의 승인 요청중 화면은 그 브라우저에서만 이어진다. 다른 브라우저·시크릿 창에서 공용 코드를 열면 새 사람으로 보여 요청을 다시 보내게 됨
