# 06. 초대코드로 참여

> 참여 성공 시 바로 그룹 내부로 이동하지 않고, 사전 등록된 멤버와 매칭하는 화면([07-join-match.md](07-join-match.md))으로 먼저 이동함.

> ⚠️ **이 화면을 작성할 담당자는 반드시 확인**: 참가자는 정식 로그인 없이도 참여할 수 있도록 결정됨. "로그인하고 참여"는 [01-login.md](01-login.md)의 이메일 회원가입/로그인 폼을 재사용함(**구글·카카오 연동은 스펙에서 제외됨**, 2026-09-12). 계좌정보는 로그인 없이 참여하는 참가자(게스트)에게 요구하지 않음. 관련 화면: [conventions.md](conventions.md#정식-회원--게스트-참가자).
>
> ✅ **게스트 재입장 인증 확정 (2026-09-12, sep10 프로토타입 기준)**: 닉네임+PIN 재입장 인증(5회 실패 시 잠금)은 스펙에서 제외됨. 게스트는 `User` 계정을 만들지 않고, 그룹 멤버 목록에서 이름만으로 참여/재참여함(재입장 시 같은 이름을 다시 고르면 그 자리로 인식되며 별도 인증 없음 — 스푸핑 방지 장치 없이 마찰을 줄이는 쪽을 택한 트레이드오프).
>
> **sep10 기준 실제 화면 구조**(작성 시 반영할 것): `screen-join-group` 단일 화면이 아니라 2단계로 나뉨.
> 1. **초대코드 입력** (`screen-join-lookup`): 코드 형식은 공용 코드(`ABCDEF`) 또는 특정 대기 중 멤버를 지정한 개인화 코드(`ABCDEF-memberId`, [12-group-invite.md](12-group-invite.md) 참고) 두 가지. 개인화 코드면 아래 2번 화면 없이 바로 그 멤버로 매칭됨
> 2. **참여하기** (`screen-join-pick`): 공용 코드인 경우 그룹 멤버 목록에서 "본인이 누구인지" 고르거나(이미 `userId`가 있는 멤버는 선택 불가 — 본인 계정으로 로그인해야 함), 목록에 없으면 로그인 여부에 따라 (로그인 안 함) 이름 입력 후 새로 참여 / (로그인함) 그대로 새 멤버로 추가
