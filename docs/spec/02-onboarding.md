# 02. 프로필 설정 (최초 온보딩)

- **담당자**: 민선
- **상태**: 작성중

## 목적

처음 가입하는 **정식 회원(이메일 가입 또는 구글·카카오 연동)** 이 정산 결과를 주고받을 계좌 정보를 등록하도록 하는 최초 1회성 화면. 이 정보가 있어야 그룹 정산 화면([09-group-settle.md](09-group-settle.md))에서 "누구에게 어느 계좌로 보내야 하는지" 안내가 가능하므로 필수 입력으로 강제한다.

> ✅ 로그인 방식 재확정 (2026-09-06): 이메일+비밀번호 회원가입/로그인 기본, 구글·카카오 로그인은 추가 연동 옵션 ([01-login.md](01-login.md) 참고). "로그인에서 넘어온 이름 자동 채움"은 구글/카카오로 가입한 경우에만 해당 — 이메일로 직접 가입한 경우 이름 정보가 없으므로 공란에서 시작함.

> ⚠️ **게스트 참가자는 이 화면을 거치지 않음.** 초대코드로 참여하면서 정식 로그인 대신 닉네임+PIN 경량 세션을 선택한 참가자는 계좌정보 등록 없이 바로 그룹에 참여함 — 계좌번호가 없어도 지출 등록/조회는 가능하고, 정산 화면에서 "돈을 받는 입장"일 때만 "계좌 미등록" 방어 문구로 대체됨. 게스트용 참여 화면은 이 문서가 아니라 [06-join-group.md](06-join-group.md)에서 다룸. 배경: [PLAN-sep03-yunjung.md](../../PLAN-sep03-yunjung.md) "결정된 질문 9" 참고.

## 주요 기능

- 구글/카카오로 가입한 경우 소셜 프로필 이름(또는 카카오 닉네임)을 이름 입력값으로 자동 채움 (수정 가능 — 실명과 다를 수 있어 사용자가 직접 고쳐 쓸 수 있게 함). 이메일로 직접 가입한 경우 자동 채움 없이 공란에서 시작
- 은행 선택 (드롭다운, 공통 은행 목록 사용 — [conventions.md](conventions.md#은행-목록))
- 계좌번호 입력
- 이름 / 은행 / 계좌 세 필드가 모두 채워져야 "시작하기" 버튼 활성화

## 진입 경로

- [01-login.md](01-login.md)에서 회원가입(이메일) 또는 로그인/연동(이메일·구글·카카오) 시도 → 로딩 화면 → 신규/기존 사용자 분기:
  - **신규 사용자** (새로 생성된 계정): 이 화면(`screen-onboarding`)으로 진입
  - **기존 사용자** (이미 `state.users`에 등록된 계정): 이 화면을 건너뛰고 바로 [03-group-list.md](03-group-list.md)로 이동
- 게스트가 정식 회원으로 전환하는 경우에도 이 화면으로 진입 — 이 경우 이름 자동 채움은 전환 시 선택한 가입 수단(이메일/구글/카카오) 기준이며, 게스트 시절 닉네임과는 무관함 (동일 인물이어도 이름이 달라질 수 있음, 별도 안내 문구는 미정)
- 뒤로가기 버튼이 없음 — 온보딩을 완료해야만 다음 단계로 넘어갈 수 있음

## UI 구성요소

- 타이틀: "계좌 등록"
- 안내 문구(guide-callout): 로그인 시 확보된 정보가 있다면 이를 언급하고, 정산 결과를 주고받을 계좌번호 등록을 안내
- 이름 입력 필드 (`ob-name`, text) — 로그인 시 이름을 확보했다면 사전 채움, 수정 가능
- 은행 선택 (`ob-bank`, select) — 첫 옵션 "은행 선택"(빈 값) + [공통 은행 목록](conventions.md#은행-목록)
- 계좌번호 입력 필드 (`ob-account`, text, placeholder "예) 1000-1234-5678")
- "시작하기" 버튼 (`ob-btn`) — 세 필드가 모두 채워지기 전까지 disabled

## 데이터

- 이 화면에서 계좌정보(`bank`, `account`)가 채워지는 `User` 엔티티. 필드 정의는 [schema.md](schema.md#user) 참고 — `User`는 [01-login.md](01-login.md)의 회원가입/로그인 단계에서 이미 생성되어 있고(`id`, `email`/`kakaoId`/`googleId`, `authProvider`, `name`), 이 화면은 계좌정보만 추가로 채우는 단계
- 저장 시점: "시작하기" 클릭(`finishOnboarding()`) 시 `state.currentUser`의 `bank`/`account`/`name`을 갱신
- 현재 프로토타입은 서버 API 없이 메모리 상태(`state`)에만 저장함 — 실제 구현 시 계좌 등록 API 연동 필요

## 액션 & 결과

| 액션 | 결과 |
|---|---|
| 이름 / 은행 / 계좌 입력 또는 변경 | `onObInput()` 실행 → 세 필드가 모두 채워졌는지 검사해 "시작하기" 버튼 활성/비활성 갱신 |
| "시작하기" 클릭 | `finishOnboarding()` 실행 → User 생성·저장 → `afterAuthed()` 호출 → [03-group-list.md](03-group-list.md) 홈 탭으로 이동 |

## 예외처리

- 세 필드 중 하나라도 비어 있으면 "시작하기" 버튼이 비활성화되어 진행할 수 없음 (별도 에러 메시지 없음)
- 계좌번호는 **형식 검증이 없음** — 숫자/하이픈 여부 등 포맷 체크 없이 입력한 텍스트가 그대로 저장됨. 실제 서비스 적용 시 은행별 계좌번호 형식 검증 필요 여부를 정책으로 정해야 함
- 이미 가입된 계정(이메일 또는 구글·카카오 연동)으로 로그인한 경우 이 화면 자체에 진입하지 않음 (진입 경로 참고)
- 게스트로 참여했던 사람이 나중에 정식 회원으로 가입/로그인하면 신규 계정 생성 기준으로는 항상 "신규 사용자"이므로 이 화면에 진입함 — 이때 과거 게스트 지출 기록의 이관(migrate) 로직이 이 화면의 "시작하기" 처리와 어떤 순서로 엮이는지는 미정 (열린 항목, [01-login.md](01-login.md) 참고)
