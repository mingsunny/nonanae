# 02. 계좌 등록 (회원가입 2단계)

> ✅ 화면 구조 갱신 (2026-09-20 sep19 프로토타입 기준): sep10에서는 회원가입 폼 하나에 이름/은행/계좌까지 다 들어 있었지만, sep19에서 회원가입이 **2단계로 분리**되면서 이 화면(`screen-signup-account`)이 다시 별도 화면으로 존재함. 1단계(이메일/비밀번호)는 [01-login.md](01-login.md)에서 다룸. 문서 파일명은 다른 문서의 링크 때문에 `02-onboarding.md`로 유지하고 제목만 실제 화면에 맞게 바꿈.

- **담당자**: 민선
- **상태**: 작성중

## 목적

회원가입 2단계로, 정산 결과를 주고받을 이름과 계좌 정보를 등록받는 화면. 이 정보가 있어야 그룹 정산 화면([09-group-settle.md](09-group-settle.md))에서 "누구에게 어느 계좌로 보내야 하는지" 안내가 가능하므로 필수 입력으로 강제한다. 이 단계를 마쳐야 계정이 실제로 생성된다.

> ✅ 로그인 방식 확정 (2026-09-12, sep10 기준): 이메일+비밀번호만 지원, 구글·카카오 연동 로그인은 스펙에서 제외됨 ([01-login.md](01-login.md) 참고). 소셜 로그인이 없으므로 이름 자동 채움 같은 동작도 없음 — 항상 공란에서 시작.

## 주요 기능

- 이름 입력 (공란에서 시작)
- 은행 선택 (드롭다운, 공통 은행 목록 사용 — [conventions.md](conventions.md#은행-목록))
- 계좌번호 입력
- 이름 / 은행 / 계좌 세 필드가 모두 채워져야 "회원가입" 버튼 활성화
- 제출 시 이메일 중복 재검사 후 계정 생성, 바로 로그인 상태로 그룹 목록 진입

## 진입 경로

- [01-login.md](01-login.md)의 회원가입 1단계에서 이메일 중복 체크를 통과하고 "다음"을 눌렀을 때
- 회원가입 도중에만 존재하는 화면 — 로그인하거나 이미 가입된 사용자는 이 화면을 거치지 않음
- 뒤로가기는 회원가입 1단계로 복귀 (입력해둔 이메일/비밀번호는 1단계 화면에 남아 있음)

## UI 구성요소

- 상단바: 뒤로가기(→ 회원가입 1단계), 타이틀 "계좌 등록"
- 안내 문구(guide-callout): "정산할 때 보낼 계좌를 바로 안내할 수 있도록 이름과 계좌 정보를 등록해주세요."
- 이름 입력 필드 (`signup-name`, text, placeholder "예) 김민지")
- 은행 선택 (`signup-bank`, select) — 첫 옵션 "은행 선택"(빈 값) + [공통 은행 목록](conventions.md#은행-목록)
- 계좌번호 입력 필드 (`signup-account`, text, placeholder "예) 1000-1234-5678")
- 에러 메시지 영역 (`signup-account-error`, 기본 숨김)
- "회원가입" 버튼 (`signup-account-btn`) — 세 필드가 모두 채워지기 전까지 disabled

## 데이터

- 이 화면에서 `User`가 **비로소 생성됨** — 1단계의 이메일/비밀번호(해시)와 이 화면의 이름/은행/계좌를 합쳐 한 번에 저장(`authProvider: 'email'`, `emailVerified: false`). 필드 정의는 [schema.md](schema.md#user) 참고
- 제출(`doSignup`) 시 `state.users`/이메일 인덱스에 저장하고 `state.currentUser`로 설정한 뒤 로그인 직후 처리로 이어짐
- 현재 프로토타입은 서버 API 없이 메모리 상태(`state`)에만 저장함 — 실제 구현 시 회원가입 API 연동 필요. 1단계에서 넘어온 입력값을 2단계까지 어디에 보관할지(클라이언트 상태 vs 서버 임시 저장)는 구현 시 결정 필요

## 액션 & 결과

| 액션 | 결과 |
|---|---|
| 이름 / 은행 / 계좌 입력 또는 변경 | 세 필드가 모두 채워졌는지 검사해 "회원가입" 버튼 활성/비활성 갱신, 에러 메시지 숨김 |
| "회원가입" 클릭 | 이메일 중복 재검사 → 통과 시 User 생성 → 로그인 상태로 [03-group-list.md](03-group-list.md) 홈 탭으로 이동 |
| 뒤로가기 | 회원가입 1단계로 복귀 |

## 예외처리

- 세 필드 중 하나라도 비어 있으면 "회원가입" 버튼이 비활성화되어 진행할 수 없음 (필드별 에러 메시지 없음)
- 제출 시 이미 가입된 이메일이면 "이미 가입된 이메일이에요. 로그인해주세요." 에러를 이 화면에 표시함 — 1단계에서 이미 검사했지만, 그 사이 다른 곳에서 같은 이메일이 가입된 경우를 위한 재검사. 다만 이 경우 사용자는 이 화면에 머물러 있어 이메일을 고치려면 1단계로 돌아가야 함
- 계좌번호는 **형식 검증이 없음** — 숫자/하이픈 여부 등 포맷 체크 없이 입력한 텍스트가 그대로 저장됨. 실제 서비스 적용 시 은행별 계좌번호 형식 검증 필요 여부를 정책으로 정해야 함
- 1단계만 마치고 이 화면에서 이탈(앱 종료 등)하면 계정이 생성되지 않음 — 다시 처음부터 가입해야 하며, 이탈 시 입력값 복원 정책은 미정
- 게스트로 참여했던 사람이 나중에 정식 회원으로 가입하면 과거 게스트 지출 기록의 이관(migrate) 로직이 이 화면의 제출 처리와 어떤 순서로 엮이는지는 미정 (열린 항목, [01-login.md](01-login.md) 참고)
