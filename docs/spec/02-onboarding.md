- **담당자**: 민선
- **상태**: 작성중 (구조 변경 확인 대기)

## 목적

처음 가입하는 **정식 회원**이 정산 결과를 주고받을 계좌 정보를 등록하도록 하는 필수 입력 단계. 이 정보가 있어야 그룹 정산 화면([09-group-settle.md](09-group-settle.md))에서 "누구에게 어느 계좌로 보내야 하는지" 안내가 가능하다.

> ✅ 로그인 방식 확정 (2026-09-12, sep10 기준): 이메일+비밀번호만 지원, 구글·카카오 연동 로그인은 스펙에서 제외됨 ([01-login.md](01-login.md) 참고).

## 주요 기능

- (sep10 기준) 이름 / 은행 / 계좌번호를 회원가입 폼에서 함께 입력받음 — 별도 자동 채움 없이 공란에서 시작
- 은행 선택 (드롭다운, 공통 은행 목록 사용 — [conventions.md](conventions.md#은행-목록))
- 이름 / 은행 / 계좌 세 필드가 모두 채워져야 다음 단계 진행 가능

## 진입 경로

- (sep10 기준) 별도 화면 진입이 없음 — [01-login.md](01-login.md)의 회원가입 폼 자체에 포함됨
- (구버전 기준, 참고용) 로그인/회원가입 후 신규 사용자에게만 별도 화면으로 노출되던 구조였음

## UI 구성요소

- (sep10 기준) [01-login.md](01-login.md)의 회원가입 폼 안에 이름/은행/계좌 입력 필드로 존재 — 별도 타이틀·화면 없음

## 데이터

- 계좌정보(`bank`, `account`)가 채워지는 `User` 엔티티. 필드 정의는 [schema.md](schema.md#user) 참고
- (sep10 기준) 회원가입 시점에 `User`가 이름/은행/계좌를 모두 포함해 한 번에 생성됨

## 액션 & 결과

| 액션 | 결과 |
|---|---|
| 이름 / 은행 / 계좌 입력 또는 변경 | 세 필드가 모두 채워졌는지 검사해 제출 버튼 활성/비활성 갱신 |

## 예외처리

- 세 필드 중 하나라도 비어 있으면 진행할 수 없음
- 계좌번호는 **형식 검증이 없음** — 숫자/하이픈 여부 등 포맷 체크 없이 입력한 텍스트가 그대로 저장됨. 실제 서비스 적용 시 은행별 계좌번호 형식 검증 필요 여부를 정책으로 정해야 함
- 게스트로 참여했던 사람이 나중에 정식 회원으로 가입하면 과거 게스트 지출 기록의 이관(migrate) 로직이 회원가입 처리와 어떤 순서로 엮이는지는 미정 (열린 항목, [01-login.md](01-login.md) 참고)
