# 02. 계좌 등록 (회원가입 2단계)

> ✅ 화면 구조 갱신 (2026-09-20 sep19 프로토타입 기준): sep10에서는 회원가입 폼 하나에 이름/은행/계좌까지 다 들어 있었지만, sep19에서 회원가입이 **2단계로 분리**되면서 이 화면(`screen-signup-account`)이 다시 별도 화면으로 존재함. 1단계(이메일/비밀번호)는 [01-login.md](01-login.md)에서 다룸. 문서 파일명은 다른 문서의 링크 때문에 `02-onboarding.md`로 유지하고 제목만 실제 화면에 맞게 바꿈.

> 🔄 회원가입 순서 변경 (2026-10-11): 예전에는 "이메일·비밀번호 → 이름·계좌 → 이메일 확인"이었지만, 지금은 **"이메일·비밀번호 → 이메일 확인 → 이름·계좌 등록 → 그룹 이동"** 이다. 이 화면(`/signup/account`)은 이제 이메일 확인 메일의 링크를 눌러 **로그인된 사람**이 이름·계좌를 처음 등록하는 마지막 단계이고, 1단계에서 계정이 먼저 만들어진다(아래 설명 중 "이 화면에서 User가 비로소 생성됨"은 폐기).

- **담당자**: 민선
- **상태**: 작성중

## 목적

회원가입 2단계로, 정산 결과를 주고받을 이름과 계좌 정보를 등록받는 화면. 이 정보가 있어야 그룹 정산 화면([09-group-settle.md](09-group-settle.md))에서 "누구에게 어느 계좌로 보내야 하는지" 안내가 가능하므로 필수 입력으로 강제한다. 이 단계를 마쳐야 계정이 실제로 생성된다.

> ✅ 로그인 방식 확정 (2026-09-12, sep10 기준): 이메일+비밀번호만 지원, 구글·카카오 연동 로그인은 스펙에서 제외됨 ([01-login.md](01-login.md) 참고). 소셜 로그인이 없으므로 이름 자동 채움 같은 동작도 없음 — 항상 공란에서 시작.

## 주요 기능

- 이름 입력 (공란에서 시작)
- 은행 선택 (드롭다운, 공통 은행 목록 사용 — [conventions.md](conventions.md#은행-목록))
- 계좌번호 입력
- 이름 / 은행 / 계좌 세 필드가 모두 채워져야 "가입 완료" 버튼 활성화 (개인정보 수집·이용 동의는 1단계로 옮김)
- 제출 시 본인 프로필(이름·은행·계좌)을 만들고 그룹 목록(또는 초대 링크로 돌아갈 곳)으로 이동

## 진입 경로

- 회원가입 1단계에서 보낸 **이메일 확인 메일의 링크**를 눌러 로그인된 직후 (링크가 이 화면으로 돌아온다. 초대 링크로 가입했다면 `?next=` 로 마친 뒤 돌아갈 곳이 함께 실린다)
- 이메일 확인이 꺼져 있으면(목업 포함) 1단계 제출 직후 바로 이 화면
- 이메일은 확인했지만 이름·계좌를 아직 등록하지 않은 계정이 **로그인하면** 이 화면으로 온다 (로그인이 필요한 화면에 가도 이 화면으로 보냄)
- 이미 프로필이 있는 회원은 이 화면을 거치지 않고 바로 다음 화면으로 간다. 로그인이 안 된 상태로 URL로 들어오면 가입 1단계로 보낸다
- 뒤로가기 버튼은 없다 (계정은 이미 만들어졌다). 대신 "나중에 하기 (로그아웃)"으로 나갈 수 있고, 계정은 남아 있어 다시 로그인하면 이 화면으로 돌아온다

## UI 구성요소

- 상단바: 타이틀 "계좌 등록" (뒤로가기 없음)
- 안내 문구(guide-callout): "이메일 확인이 끝났어요. 정산할 때 보낼 계좌를 바로 안내할 수 있도록 이름과 계좌 정보를 등록해주세요."
- 이름 입력 필드 (`signup-name`, text, placeholder "예) 김민지")
- 은행 선택 (`signup-bank`, select) — 첫 옵션 "은행 선택"(빈 값) + [공통 은행 목록](conventions.md#은행-목록)
- 계좌번호 입력 필드 (`signup-account`, text, placeholder "예) 1000-1234-5678")
- 에러 메시지 영역 (`signup-account-error`, 기본 숨김)
- "가입 완료" 버튼 (`signup-account-btn`) — 세 필드가 모두 채워지기 전까지 disabled
- "나중에 하기 (로그아웃)" 텍스트 링크

## 데이터

- ~~이 화면에서 `User`가 **비로소 생성됨**~~ (폐기, 2026-10-11 — 계정은 1단계에서 만들어지고, 이 화면은 프로필만 만든다. 아래는 옛 서술) — 1단계의 이메일/비밀번호(해시)와 이 화면의 이름/은행/계좌를 합쳐 한 번에 저장(`authProvider: 'email'`, `emailVerified: false`). 필드 정의는 [schema.md](schema.md#user) 참고
- 제출(`doSignup`) 시 `state.users`/이메일 인덱스에 저장하고 `state.currentUser`로 설정한 뒤 로그인 직후 처리로 이어짐
- 현재 프로토타입은 서버 API 없이 메모리 상태(`state`)에만 저장함 — 실제 구현 시 회원가입 API 연동 필요. 1단계에서 넘어온 입력값을 2단계까지 어디에 보관할지(클라이언트 상태 vs 서버 임시 저장)는 구현 시 결정 필요

## 액션 & 결과

| 액션 | 결과 |
|---|---|
| 이름 / 은행 / 계좌 입력 또는 변경 | 세 필드가 모두 채워졌는지 검사해 "가입 완료" 버튼 활성/비활성 갱신, 에러 메시지 숨김 |
| "가입 완료" 클릭 | 프로필(이름·은행·계좌) 생성 → [03-group-list.md](03-group-list.md) 홈 탭(또는 초대 링크로 돌아갈 곳)으로 이동 |
| "나중에 하기 (로그아웃)" | 로그아웃하고 인트로로 이동. 계정은 남는다 |

## 예외처리

- 세 필드 중 하나라도 비어 있으면 "회원가입" 버튼이 비활성화되어 진행할 수 없음 (필드별 에러 메시지 없음)
- (폐기) 제출 시 이미 가입된 이메일이면 "이미 가입된 이메일이에요. 로그인해주세요." 에러를 이 화면에 표시함 — 이메일은 1단계에서 이미 계정이 되어 이 화면에서는 일어나지 않는다. 옛 서술: — 1단계에서 이미 검사했지만, 그 사이 다른 곳에서 같은 이메일이 가입된 경우를 위한 재검사. 다만 이 경우 사용자는 이 화면에 머물러 있어 이메일을 고치려면 1단계로 돌아가야 함
- 계좌번호는 **형식 검증이 없음** — 숫자/하이픈 여부 등 포맷 체크 없이 입력한 텍스트가 그대로 저장됨. 실제 서비스 적용 시 은행별 계좌번호 형식 검증 필요 여부를 정책으로 정해야 함
- 이 화면에서 이탈(앱 종료 등)해도 계정은 남는다 — 이메일 확인은 끝났으므로 다시 로그인하면 이 화면으로 돌아온다. 이름·계좌를 등록하기 전에는 그룹을 만들거나 참여할 수 없다(DB가 프로필 없는 계정의 그룹 참여를 막음)
- 게스트로 참여했던 사람이 나중에 정식 회원으로 가입하면 과거 게스트 지출 기록의 이관(migrate) 로직이 이 화면의 제출 처리와 어떤 순서로 엮이는지는 미정 (열린 항목, [01-login.md](01-login.md) 참고)
