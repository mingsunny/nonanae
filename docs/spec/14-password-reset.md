# 14. 비밀번호 재설정

> 신규 화면 — 로그인 기본 수단이 이메일+비밀번호로 확정되면서 필요해짐. 이 화면을 작성할 담당자는 반드시 확인: (1) 재설정 메일 발송 대상 이메일이 존재하는지 여부를 화면에 노출하지 말 것(계정 존재 여부 유추 방지 — [01-login.md](01-login.md) 예외처리와 동일한 원칙), (2) 재설정 토큰의 만료 시간과 1회성 여부. 근거: [PLAN-sep03-yunjung.md](../../PLAN-sep03-yunjung.md) "결정된 질문 10" 참고.

## 목적

이메일+비밀번호로 로그인하는 사용자가 비밀번호를 잊었을 때, 본인 이메일로 받은 링크를 통해 새 비밀번호를 설정할 수 있게 하는 화면.

## 주요 기능

- 이메일 입력 → 재설정 링크 발송 요청 (1단계)
- 이메일로 받은 링크로 진입해 새 비밀번호 설정 (2단계)
- 재설정 완료 후 로그인 화면으로 복귀

## 진입 경로

- [01-login.md](01-login.md)의 "비밀번호를 잊으셨나요?" 링크 (현재 sep10 프로토타입에는 없음 — 위 콜아웃 참고, 추가 여부 결정 필요)
- 이메일로 발송된 재설정 링크(토큰 포함 URL) 클릭 시 2단계 화면으로 직접 진입

## UI 구성요소

**1단계 — 이메일 입력**
- 안내 문구: "가입하신 이메일을 입력하시면 비밀번호 재설정 링크를 보내드려요"
- 이메일 입력 필드
- "재설정 링크 보내기" 버튼
- "로그인으로 돌아가기" 링크

**발송 완료 안내**
- "입력하신 이메일로 재설정 링크를 보냈어요" — 해당 이메일로 가입된 계정이 실제로 존재하는지와 무관하게 항상 동일한 문구 노출 (아래 예외처리 참고)

**2단계 — 새 비밀번호 설정** (이메일 링크로 진입)
- 새 비밀번호 입력 필드
- 비밀번호 확인 입력 필드 (일치 여부 실시간 표시, [01-login.md](01-login.md) 회원가입 폼과 동일한 패턴)
- "비밀번호 변경" 버튼

## 데이터

- `User.email`로 계정 조회 → 존재하면 재설정 토큰 생성 후 이메일 발송. 토큰 저장을 위한 필드(예: `passwordResetToken`, `passwordResetExpiresAt`)는 [schema.md](schema.md#user)에 아직 정의돼 있지 않음 — 이 화면이 확정되면 추가 필요
- 2단계에서 토큰 유효성(만료 여부, 1회 사용 여부) 확인 후 `User.passwordHash`를 새 값으로 갱신, 토큰은 즉시 무효화

## 액션 & 결과

| 액션 | 결과 |
|---|---|
| 이메일 제출 | 계정 존재 여부와 무관하게 "재설정 링크를 보냈어요" 동일 안내 표시 |
| 재설정 링크 클릭 (유효한 토큰) | 새 비밀번호 입력 화면(2단계)으로 진입 |
| 새 비밀번호 제출 (확인값 일치) | 비밀번호 변경 → 토큰 무효화 → [01-login.md](01-login.md)로 이동, "비밀번호가 변경되었습니다" 안내 |

## 예외처리

- 존재하지 않는 이메일을 제출해도 성공 메시지와 동일하게 응답 — 계정 존재 여부가 노출되면 이메일 목록 무차별 대입에 악용될 수 있음 ([01-login.md](01-login.md) 예외처리와 동일한 원칙)
- 만료되었거나 이미 사용된 토큰으로 2단계 화면에 접근 시 에러 안내 + 재요청 유도
- 새 비밀번호와 확인 값이 다르면 제출 불가
- 비밀번호 최소 요구사항(길이/구성)은 [01-login.md](01-login.md) 회원가입과 동일 정책을 따라야 하나, 그쪽도 아직 미정
- 재설정 요청 남용 방지(동일 이메일/IP 반복 요청 rate limit) 정책 미정
- 토큰 만료 시간 자체가 미정 (일반적으로 30분~1시간 권장, 정책 결정 필요)
