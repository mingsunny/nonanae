# 01. 로그인 / 회원가입

> ✅ 로그인 방식 재확정 (2026-09-06, 이전 결정을 뒤집음): **이메일+비밀번호 회원가입/로그인을 기본으로 하고, 구글·카카오 로그인은 추가 연동 옵션**으로 지원. 카카오 단독 로그인이었던 이전 버전에서 전환됨. 이 화면은 앱을 초대코드 없이 직접 실행했을 때(그룹장, 또는 정식 회원 전환을 원하는 사용자)만 진입하는 화면임 — 초대링크/코드로 들어오는 참가자는 이 화면을 거치지 않고 [06-join-group.md](06-join-group.md)의 "닉네임으로 참여 / 정식 로그인" 분기로 먼저 진입함 (아래 "게스트 참가자 분기" 참고). 자세한 스코프 결정 배경은 [PLAN-sep03-yunjung.md](../../PLAN-sep03-yunjung.md) "결정된 질문 10" 참고.

- **담당자**: 민선
- **상태**: 작성중

## 목적

앱을 사용하기 위해 사용자를 식별(이메일 계정 생성 또는 구글·카카오 연동)하고, 이후 정산 데이터(그룹/지출)를 특정 사용자에 귀속시키기 위한 최초 진입 화면.

## 주요 기능

- 이메일 회원가입 (이메일, 비밀번호, 비밀번호 확인 입력)
- 이메일 로그인 (이메일, 비밀번호 입력)
- 로그인 / 회원가입 화면 전환
- "구글로 계속하기" / "카카오로 계속하기" 버튼 — 클릭 시 각 OAuth로 리다이렉트, 반환된 이메일 기준으로 기존 계정 연동 또는 신규 계정 생성 (동의항목: 구글은 기본 스코프의 이메일+프로필, 카카오는 닉네임+카카오계정(이메일))
- "비밀번호를 잊으셨나요?" 링크 → 비밀번호 재설정 화면으로 이동 (신규 화면, 아직 스펙 미작성 — [handoff.md](handoff.md) 참고)
- 로그인/회원가입 처리 중 로딩 상태 표시
- 로그인 성공 시 신규 / 기존 사용자 여부에 따라 다음 화면 분기

### 게스트 참가자 분기

- **이 화면은 정식 회원(이메일 가입 또는 구글·카카오 연동)만을 위한 진입점**. 초대코드로 들어오는 참가자는 정식 로그인 없이 "닉네임+PIN 경량 세션"으로도 참여할 수 있음 — 그 분기 로직은 이 화면이 아니라 [06-join-group.md](06-join-group.md)에서 처리됨
- 게스트로 참여했던 사용자가 이후 정식 회원으로 전환하고 싶을 때(계좌 등록 등 정식 기능이 필요해질 때)는 이 화면(이메일 가입 또는 구글·카카오 연동)을 재사용 — 로그인/가입 성공 시 기존 게스트의 지출 기록을 새 정식 계정으로 이관(migrate)하는 로직이 필요함 (진입 경로에 게스트발 전환인지 여부를 함께 전달해야 함 — 상세 미정, 열린 항목)

## 진입 경로

- 앱을 처음 실행했을 때 진입하는 시작 화면. 별도 진입 경로 없음 (최초 화면)
- 게스트 참가자가 그룹 화면에서 "로그인하고 계좌 등록하기" 등으로 정식 회원 전환을 시도하는 경우에도 이 화면(또는 동일 로직)을 재사용 — 진입 지점 UI는 미정
- 비밀번호 재설정 완료 후 다시 이 화면(로그인 폼)으로 복귀

## UI 구성요소

- 타이틀: 서비스명
- 안내 문구 (guide-callout)
- 로그인 / 회원가입 전환 탭 또는 링크
- **로그인 폼**: 이메일 입력, 비밀번호 입력, "로그인" 버튼, "비밀번호를 잊으셨나요?" 링크
- **회원가입 폼**: 이메일 입력, 비밀번호 입력, 비밀번호 확인 입력, "회원가입" 버튼
- 구분선("또는") + "구글로 계속하기" 버튼, "카카오로 계속하기" 버튼

### 로그인 처리 중 (로딩 상태)

- 로그인/회원가입 시도 후 짧게 노출되는 로딩 스피너 화면 (현재 프로토타입 기준 약 0.7초 뒤 자동 진행 — 실제 구현에서는 서버 응답 시간에 따라 달라짐)

## 데이터

- 식별에 사용하는 값: 이메일 가입/로그인은 `User.email`, 구글·카카오 연동은 `User.google_id`/`User.kakao_id`. [schema.md](schema.md#user) 참고
- 회원가입: 이메일 중복 체크 → 비밀번호를 bcrypt로 해시해 `password_hash`에 저장 → `auth_provider: 'email'` → 인증 메일 발송(`email_verified: false`로 시작)
- 로그인: 이메일로 `User` 조회 → `password_hash`와 bcrypt 비교
- 구글/카카오 버튼: OAuth 콜백에서 받은 이메일로 기존 `User` 조회 → 있으면 해당 소셜 id 필드만 채워 연동, 없으면 신규 `User` 생성(`auth_provider: 'google'|'kakao'`, `password_hash: null`)
- 로그인 성공 시 신규/기존 사용자 여부를 조회하여 분기
- 게스트 → 정식 회원 전환 시: 기존 게스트 `User`(`auth_provider: 'guest'`)의 `expense_participants`/`paid_by` 참조를 새로 생성/연동된 정식 `User`의 id로 이관

## 예외처리

- 이미 가입된 이메일로 회원가입 시도 → 에러 메시지와 함께 로그인 유도 (구체 문구 미정)
- 로그인 실패(미가입 이메일 또는 비밀번호 불일치) → 어느 쪽이 틀렸는지 구분해서 알려주지 않고 "이메일 또는 비밀번호가 올바르지 않습니다"로 통일 — 계정 존재 여부가 에러 메시지로 노출되면 이메일 목록 무차별 대입에 악용될 수 있음
- 로그인 시도 브루트포스 방지 — 동일 이메일 또는 IP 기준 반복 실패 시 일시 잠금 필요 (구체 임계값/잠금 시간 미정. 게스트 PIN 잠금 정책(5회 실패 시 15분)과 통일할지는 열린 항목)
- 비밀번호 최소 요구사항(길이/구성) 미정 — 정책 결정 필요
- 이메일 인증 필수 여부 미정 — 인증 전에도 앱 이용을 허용할지(마찰 최소화) 아니면 인증을 강제할지(보안 강화) 열린 항목. 최소한 비밀번호 재설정 메일은 인증된 이메일로만 발송되어야 함
- **구글/카카오 연동 시 계정 탈취 위험**: 소셜 제공자가 반환한 이메일이 기존 이메일 가입 계정과 일치한다고 해서 무조건 자동 연동하면, 소셜 제공자가 이메일 소유를 검증하지 않는 경우(예: 검증 안 된 이메일을 동의항목으로 제공하는 경우) 공격자가 타인의 이메일로 소셜 계정을 만들어 기존 계정에 침투할 수 있음 — 자동 연동 전 이메일 인증 여부 확인 또는 "이미 가입된 이메일입니다, 비밀번호로 로그인 후 연동하세요" 방식으로 우회하는 정책이 필요 (구현 전 반드시 결정, [PLAN-sep03-yunjung.md](../../PLAN-sep03-yunjung.md) 데이터베이스 스키마 섹션 참고)
- 카카오/구글 로그인 실패·거부, 네트워크 오류 시 UX는 현재 정의돼 있지 않음
- 게스트 → 정식 회원 전환 중 이관 실패(네트워크 오류 등) 시 게스트 세션이 유지되는지, 재시도 가능한지 — 미정
