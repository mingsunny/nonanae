# 01. 로그인 / 회원가입

> ✅ 로그인 방식 확정 (2026-09-10 sep10 프로토타입 기준, 이전 결정에서 변경): **이메일+비밀번호만 지원, 구글·카카오 연동 로그인은 스펙에서 제외**. 직전 결정("이메일 기본 + 구글·카카오 추가 연동")에서 소셜 로그인 자체를 걷어내는 것으로 축소됨. 이 화면은 앱을 초대코드 없이 직접 실행했을 때(그룹장, 또는 정식 회원 전환을 원하는 사용자)만 진입하는 화면임 — 초대링크/코드로 들어오는 참가자는 이 화면을 거치지 않고 [06-join-group.md](06-join-group.md)의 참여 흐름으로 먼저 진입함 (아래 "게스트 참가자 분기" 참고).
>
> ✅ 게스트 인증 방식 확정 (2026-09-12): 참가자용 닉네임+PIN 재입장 인증(5회 실패 시 잠금)은 스펙에서 제외됨. 게스트는 `User` 계정 자체를 만들지 않고, 초대코드로 참여할 때 이름만 입력하면 됨 — 재입장도 같은 이름을 다시 고르는 방식으로 별도 인증 없음. 자세한 내용은 [06-join-group.md](06-join-group.md), [conventions.md](conventions.md#정식-회원--게스트-참가자) 참고.

- **담당자**: 민선
- **상태**: 작성중

## 목적

앱을 사용하기 위해 사용자를 이메일 계정으로 식별하고, 이후 정산 데이터(그룹/지출)를 특정 사용자에 귀속시키기 위한 최초 진입 화면.

## 주요 기능

- 이메일 회원가입 (이메일, 비밀번호, 비밀번호 확인 입력)
- 이메일 로그인 (이메일, 비밀번호 입력)
- 로그인 / 회원가입 화면 전환
- 로그인 성공 시 신규 / 기존 사용자 여부에 따라 다음 화면 분기
- "친구에게 받은 초대코드가 있어요" 링크 — 로그인 없이 바로 초대코드 참여 흐름([06-join-group.md](06-join-group.md))으로 진입

### 게스트 참가자 분기

- **이 화면은 정식 회원(이메일 가입)만을 위한 진입점**. 초대코드로 들어오는 참가자는 정식 로그인 없이도 참여할 수 있음 — 그 분기 로직은 이 화면이 아니라 [06-join-group.md](06-join-group.md)에서 처리됨
- 게스트로 참여했던 사용자가 이후 정식 회원으로 전환하고 싶을 때(계좌 등록 등 정식 기능이 필요해질 때)는 이 화면(이메일 회원가입)을 재사용 — 가입 성공 시 기존 게스트의 지출 기록을 새 정식 계정으로 이관(migrate)하는 로직이 필요함 (진입 경로에 게스트발 전환인지 여부를 함께 전달해야 함 — 상세 미정, 열린 항목)

## 진입 경로

- 앱을 처음 실행했을 때 진입하는 시작 화면. 별도 진입 경로 없음 (최초 화면)
- 게스트 참가자가 그룹 화면에서 정식 회원 전환을 시도하는 경우에도 이 화면(또는 동일 로직)을 재사용 — 진입 지점 UI는 미정

## UI 구성요소

- 타이틀: 서비스명
- 안내 문구 (guide-callout)
- **로그인 폼**: 이메일 입력, 비밀번호 입력, 에러 메시지 영역, "로그인" 버튼
- "회원가입" 버튼 → [screen-signup] 화면으로 이동
- "친구에게 받은 초대코드가 있어요" 텍스트 링크
- **회원가입 폼** (별도 화면): 이메일, 비밀번호, 비밀번호 확인(일치 여부 실시간 표시), 이름, 은행, 계좌번호 — 온보딩 단계 없이 가입 시점에 계좌정보까지 한 번에 입력받음 ([02-onboarding.md](02-onboarding.md) 참고, 현재 이 폼이 그 역할을 흡수한 상태)

## 데이터

- 식별에 사용하는 값: `User.email`. [schema.md](schema.md#user) 참고
- 회원가입: 이메일 중복 체크 → 비밀번호 해시해 저장 → `User` 생성(`authProvider: 'email'`, 이름/은행/계좌 포함)
- 로그인: 이메일로 `User` 조회 → 비밀번호 해시 비교
- 로그인 성공 시 신규/기존 사용자 여부를 조회하여 분기
- 게스트 → 정식 회원 전환 시: 기존 게스트 `User`(`authProvider: 'guest'`)의 지출 참여/결제 기록을 새 정식 `User`의 id로 이관

## 액션 & 결과

| 액션 | 결과 |
|---|---|
| 이메일 회원가입 제출 | 이메일 중복 체크 → 통과 시 계정 생성(이름/은행/계좌 포함) → [03-group-list.md](03-group-list.md)로 이동 |
| 이메일 로그인 제출 | 자격 검증 → `email` 기준으로 기존/신규 사용자 분기 |
| "회원가입" 버튼 클릭 | 회원가입 화면으로 이동 (로그인 화면에 입력했던 이메일 값 유지) |
| "친구에게 받은 초대코드가 있어요" 클릭 | [06-join-group.md](06-join-group.md) 초대코드 입력 화면으로 이동 (로그인 여부와 무관) |

## 예외처리

- 이미 가입된 이메일로 회원가입 시도 → "이미 가입된 이메일이에요. 로그인해주세요." 에러 메시지
- 로그인 실패(미가입 이메일 또는 비밀번호 불일치) → 어느 쪽이 틀렸는지 구분하지 않고 "이메일 또는 비밀번호가 일치하지 않아요"로 통일 — 계정 존재 여부가 에러 메시지로 노출되면 이메일 목록 무차별 대입에 악용될 수 있음
- 로그인 시도 브루트포스 방지 정책 미정 (임계값/잠금 시간 결정 필요)
- 비밀번호 최소 요구사항(길이/구성) 미정 — 정책 결정 필요
- 이메일 인증 절차 자체가 현재 스펙에 없음 — 인증 필요 여부 정책 결정 필요
- 게스트 → 정식 회원 전환 중 이관 실패(네트워크 오류 등) 시 게스트 세션이 유지되는지, 재시도 가능한지 — 미정
