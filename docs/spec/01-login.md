# 01. 인트로 / 로그인 / 회원가입

> ✅ 로그인 방식 확정 (2026-09-10 sep10 프로토타입 기준, 이전 결정에서 변경): **이메일+비밀번호만 지원, 구글·카카오 연동 로그인은 스펙에서 제외**. 직전 결정("이메일 기본 + 구글·카카오 추가 연동")에서 소셜 로그인 자체를 걷어내는 것으로 축소됨.
>
> ✅ 첫 화면 구조 변경 (2026-09-20 sep19 프로토타입 기준): 앱을 열면 로그인 폼이 아니라 **인트로 화면**이 먼저 뜨고, 거기서 로그인 / 회원가입 / 초대코드 참여로 갈라짐. 회원가입은 **2단계**로 분리됨 — 1단계(이메일/비밀번호)는 이 문서, 2단계(이름/은행/계좌)는 [02-onboarding.md](02-onboarding.md)에서 다룸.
>
> ✅ 게스트 인증 방식 확정 (2026-09-12): 참가자용 닉네임+PIN 재입장 인증(5회 실패 시 잠금)은 스펙에서 제외됨. 게스트는 `User` 계정 자체를 만들지 않고, 초대코드로 참여할 때 이름만 입력하면 됨 — 재입장도 같은 이름을 다시 고르는 방식으로 별도 인증 없음. 자세한 내용은 [06-join-group.md](06-join-group.md), [conventions.md](conventions.md#정식-회원--게스트-참가자) 참고.

- **담당자**: 민선
- **상태**: 작성중

## 목적

앱의 첫 진입점. 서비스를 소개하고, 이메일 계정으로 로그인/가입하거나 초대코드로 바로 그룹에 참여하는 세 갈래 길을 제공한다. 로그인·가입은 이후 정산 데이터(그룹/지출)를 특정 사용자에 귀속시키기 위한 단계다.

## 주요 기능

- 인트로 화면에서 로그인 / 회원가입 / 초대코드 참여로 분기
- 이메일 로그인 (이메일, 비밀번호 입력)
- 이메일 회원가입 1단계 (이메일, 비밀번호, 비밀번호 확인 입력, 이메일 중복 체크) → 2단계 [02-onboarding.md](02-onboarding.md)
- 비밀번호 확인 일치 여부 실시간 표시
- 로그인 / 회원가입 화면 간 전환 ("이미 계정이 있으신가요? 로그인")

### 게스트 참가자 분기

- **이 문서의 로그인/가입은 정식 회원(이메일 가입)만을 위한 흐름**. 초대코드로 들어오는 참가자는 정식 로그인 없이도 참여할 수 있음 — 인트로의 "초대코드로 가입하기"에서 [06-join-group.md](06-join-group.md)로 이동하며, 분기 로직은 그쪽에서 처리됨
- 게스트로 참여했던 사용자가 이후 정식 회원으로 전환하고 싶을 때(계좌 등록 등 정식 기능이 필요해질 때)는 이 회원가입 흐름을 재사용 — 가입 성공 시 기존 게스트의 지출 기록을 새 정식 계정으로 이관(migrate)하는 로직이 필요함 (진입 경로에 게스트발 전환인지 여부를 함께 전달해야 함 — 상세 미정, 열린 항목)

## 진입 경로

- **인트로**: 앱을 처음 실행했을 때의 시작 화면. 별도 진입 경로 없음
- **로그인 / 회원가입 1단계**: 인트로의 "로그인" / "회원가입" 버튼. 두 화면 모두 뒤로가기는 인트로로 돌아감
- 로그아웃·회원탈퇴 후에는 인트로가 아니라 **로그인 화면**으로 이동함 ([04-profile.md](04-profile.md) 참고)
- 초대코드 입력 화면([06-join-group.md](06-join-group.md))에서 비로그인 상태로 뒤로가기 시 인트로로 복귀
- 게스트 참가자가 정식 회원 전환을 시도하는 경우에도 회원가입 흐름을 재사용 — 진입 지점 UI는 미정

## UI 구성요소

**인트로** (`screen-intro`)
- 브랜드 영역: 코인(₩) 배지 + 스파크 장식, 타이틀 "노나내", 태그라인 "여행에서 함께 쓴 돈, 가장 간단하게 나눠 정산해요."
- "로그인" 버튼 (primary), "회원가입" 버튼 (outline)
- "초대코드로 가입하기" 텍스트 링크 → 로그인 없이 초대코드 참여 흐름으로 진입. 문구는 "가입"이지만 실제로는 가입 없이 참여하는 경로임(문구와 동작 불일치 — 정리 필요)

**로그인** (`screen-login`)
- 상단바: 뒤로가기(→ 인트로), 타이틀 "로그인"
- 이메일 입력, 비밀번호 입력 (placeholder 없음), 에러 메시지 영역
- "로그인" 버튼 — 이메일에 `@`가 있고 비밀번호가 비어있지 않아야 활성화
- sep10과 달리 이 화면에는 "회원가입" 버튼과 초대코드 링크가 없음 (인트로로 이동)

**회원가입 1단계** (`screen-signup`)
- 상단바: 뒤로가기(→ 인트로), 타이틀 "회원가입"
- 이메일, 비밀번호(placeholder "8자 이상"), 비밀번호 확인 입력
- 비밀번호 일치 여부 문구 ("비밀번호가 일치해요." / "비밀번호가 일치하지 않아요.")
- 에러 메시지 영역, "다음" 버튼 — 이메일에 `@`가 있고, 비밀번호가 입력되고, 확인 값과 일치해야 활성화
- "이미 계정이 있으신가요? 로그인" 링크

## 데이터

- 식별에 사용하는 값: `User.email`. [schema.md](schema.md#user) 참고
- 회원가입 1단계에서는 **User를 만들지 않음** — 입력값은 화면에만 머물고, 2단계 완료(`doSignup`) 시점에 이메일/비밀번호 해시/이름/은행/계좌를 합쳐 `User`(`authProvider: 'email'`)를 한 번에 생성 ([02-onboarding.md](02-onboarding.md) 참고)
- 이메일 중복 체크는 1단계("다음" 클릭)와 최종 제출 시 두 번 수행됨
- 로그인: 이메일로 `User` 조회 → 비밀번호 해시 비교 → 성공 시 [03-group-list.md](03-group-list.md)로 이동
- 게스트 → 정식 회원 전환 시: 게스트로 참여했던 `Member`의 지출 참여/결제 기록을 새 정식 `User`에 연결

## 예외처리

- 이미 가입된 이메일로 회원가입 시도 → 1단계에서 "이미 가입된 이메일이에요. 로그인해주세요." 에러 메시지 (2단계 최종 제출 시에도 재검사)
- 로그인 실패(미가입 이메일 또는 비밀번호 불일치) → 어느 쪽이 틀렸는지 구분하지 않고 "이메일 또는 비밀번호가 일치하지 않아요"로 통일 — 계정 존재 여부가 에러 메시지로 노출되면 이메일 목록 무차별 대입에 악용될 수 있음
- 비밀번호 입력란 placeholder는 "8자 이상"이지만 **실제로 길이를 검증하지 않음** (입력되어 있고 확인 값과 일치하기만 하면 통과) — 최소 요구사항(길이/구성) 정책 결정 필요
- 이메일 형식 검증이 `@` 포함 여부뿐 — 정식 형식 검증 정책 미정
- 로그인 시도 브루트포스 방지 정책 미정 (임계값/잠금 시간 결정 필요)
- 이메일 인증 절차 자체가 현재 스펙에 없음 — 인증 필요 여부 정책 결정 필요
- 로그인 화면에 "비밀번호를 잊으셨나요?" 진입 링크가 없음 — [14-password-reset.md](14-password-reset.md) 필요 여부 미정
- 게스트 → 정식 회원 전환 중 이관 실패(네트워크 오류 등) 시 게스트 세션이 유지되는지, 재시도 가능한지 — 미정
