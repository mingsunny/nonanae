# 10. 그룹 요약 (카테고리별 / 인원별)

> 기존 인원별/카테고리별 토글 방식에서, 두 섹션을 한 화면에 세로로 나열하는 방식으로 변경됨. 그룹 내부 탭 중 세 번째("요약") 탭.

그룹 지출을 카테고리별 비중과 인원별 결제·잔액 두 관점에서 한눈에 보여주는 화면.

- **담당자**:
- **상태**: 초안

## 1. 화면 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | 10_group_summary |
| 역할 | 카테고리별 지출 비중 + 인원별 결제/잔액 조회 (읽기 전용) |
| 진입 경로 | 그룹 내부 하단 탭바 "요약" 탭 |
| 같은 그룹 내 탭 전환 | 08 지출 / 09 정산 |
| 다음 화면 | 없음 (조회 전용, 탭 전환 외 이동 없음) |

## 2. 진입 조건

- 08 §2와 동일한 그룹 멤버 조건

## 3. UI 구성

### 3.1 헤더

- 08 §3.1과 동일(08/09/10 공용)

### 3.2 하단 탭바 (그룹 내부 GNB)

- 08 §3.2와 동일(08/09/10 공용) — 현재 탭은 "요약"

### 3.3 카테고리별

- 전체 지출 대비 카테고리 비중을 하나의 스택바(가로 막대)로 표현, 금액이 있는 카테고리만 금액 내림차순으로 정렬
- 막대 아래에 카테고리별 범례: 색상 스와치, 카테고리명, 금액, 비율(%)

### 3.4 인원별

- 멤버별 행: 아바타, 이름(본인은 "(나)" 표기), 결제 금액("결제 ₩X")
- 같은 행 우측에 잔액 상태: 받을 돈(양수, teal 계열) / 보낼 돈(음수, brick 계열, 절대값 표시) / 정산 완료(0, "—")
- 카테고리별·인원별 둘 다 토글 없이 세로로 순서대로 배치(카테고리별 → 인원별). 과거엔 토글로 전환하는 방식이었으나 제거됨

## 4. 기능

| 기능 | 동작 |
|---|---|
| 헤더 back | 08 §4와 동일 — 항상 03 그룹 목록으로 이동 |

## 5. 데이터

- 카테고리별 합계: 지출을 `category`로 그룹핑해서 합산 — PLAN 문서 §정산 알고리즘의 "카테고리별 집계" 참고(단, PLAN 문서는 이 화면을 옛 번호인 "05번 스펙"으로 지칭하고 있음 — 화면 재정리 후 지금은 10번이라 참조 번호가 갱신 필요)
- 인원별 balance(잔액) / paid(결제 합): PLAN 문서 §정산 알고리즘 참고 — 09와 같은 계산을 공유하지만, `paid`를 사람별로 화면에 직접 보여주는 건 09가 아니라 이 화면의 역할(09 §5 참고)
- 카테고리 6종: PLAN 스키마의 Category enum(식비/숙소/교통/쇼핑/액티비티/기타)과 동일

## 6. 예외 처리

| 상황 | 처리 |
|---|---|
| 지출이 아직 없음 | 카테고리별·인원별 두 섹션에 각각 독립적으로 "아직 등록된 지출이 없어요." 노출(한쪽만 비는 상황은 실제로 없지만 렌더링 로직 자체가 두 섹션으로 분리되어 있음) |
