# 07. 초대 대기 멤버 매칭

> 초대코드 참여(06) 이후, 이미 그룹에 사전 등록된(앱 미가입 상태로 이름만 추가된) 멤버 중 본인이 있으면 선택해 매칭하는 화면.

> ⚠️ **이 화면을 작성할 담당자는 반드시 확인**: [12-group-invite.md](12-group-invite.md)의 "앱 미가입 상태로 이름만 추가된 멤버(placeholder)"와 [06-join-group.md](06-join-group.md)의 "로그인 없이 참가(게스트)"는 데이터 구조상 완전히 동일함(`Member.userId`가 null, `Member.name`만 있음) — 매칭 대상자는 (1) 정식 로그인(이메일 가입)으로 들어와 `userId`가 채워지는 경우, (2) 로그인 없이 그대로 게스트(`userId`는 계속 null)로 남는 경우 둘 다 가능함(**구글·카카오 연동은 스펙에서 제외**, 2026-09-12). placeholder가 정식 회원으로 매칭되면 그 Member의 `userId`만 채우면 되고(id는 그대로 유지되어 기존 지출 기록이 자동으로 연결됨), 게스트로 참여하는 경우도 마찬가지로 별도 이관 로직 없이 그 Member를 그대로 씀. 로그인 없이 참가한 경우 계좌정보는 계속 없음. 배경: [PLAN-sep03-yunjung.md](../../PLAN-sep03-yunjung.md) "결정된 질문 9" 참고.
>
> ✅ **게스트 재입장 인증 확정 (2026-09-12)**: PIN 등 별도 인증 없음. sep10에서는 이 화면(`screen-join-match`)이 `screen-join-pick`으로 대체됨 — 초대코드 확인 후 그룹 멤버 목록에서 "본인이 누구인지" 고르거나(이미 `userId`가 채워진 멤버는 선택 불가), 없으면 (로그인 안 한 경우) 이름만 입력해 새로 참여, (로그인한 경우) 그냥 새 멤버로 추가됨. 재입장(같은 사람이 다시 들어오는 경우)도 이 화면에서 같은 이름을 다시 고르는 것으로 처리되며 본인 확인 절차는 없음.
