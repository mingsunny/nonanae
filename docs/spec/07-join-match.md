# 07. 그룹 초대 (공용 코드로 참여)

> ✅ **2026-10-17 개편**: 예전 "참여하기 (멤버 매칭)" 화면 — 그룹 멤버 목록에서 "본인이 누구인지 골라주세요" — 은 **모든 곳에서 삭제**됐다. 공용 코드로 들어오면 이 "그룹 초대" 화면에서 **새 멤버로** 참여를 요청한다. 그룹장이 미리 추가해 둔 사람(대기 중 멤버)을 그 자리로 연결하려면 [12](12-group-invite.md)의 "초대 보내기"로 받은 개인 초대 링크를 써야 한다([06](06-join-group.md) 초대 화면). 전체 흐름은 [06 유저 플로우](06-join-group.md#유저-플로우-2026-10-17).
>
> 예전 화면의 결정 기록(게스트 재입장 PIN 제외, placeholder와 게스트가 같은 데이터 구조라는 점 등)은 아래 변경이력과 [conventions.md](conventions.md#정식-회원--게스트-참가자)에 남아 있다.

- **담당자**: 민선
- **상태**: 작성중

## 목적

공용 초대코드(또는 공용 링크)로 들어온 사람이 그룹 이름을 확인하고, 한 번에 그룹장에게 참여를 요청하는 화면. 정보를 최소로 줄여 버튼 하나로 끝나게 한다.

## 진입 경로

- [06-join-group.md](06-join-group.md)에서 공용 코드를 확인한 뒤
- 개인 초대 링크인데 그 자리가 이미 회원 계정에 연결된 경우(로그인 상태)
- 거절됨 화면의 "다시 요청하기"(공용 코드로 요청했던 경우)

## UI 구성요소

- 상단바: 뒤로가기(→ 06 코드 입력), 타이틀 "그룹 초대"
- "초대받은 그룹" 카드: 그룹 이름
- **로그인 상태**: "{내 이름}님으로 참여하기" 버튼 하나
- **비로그인 상태**:
  - "이름" 입력 필드(placeholder "예) 김민지", 20자 제한) + "이 이름으로 참여하기" 버튼(입력 전까지 disabled)
  - 그 아래 "로그인" / "회원가입" 버튼 나란히 — 마치면 같은 링크로 돌아옴
  - 안내 "참여하면 입력한 이름이 이 그룹 멤버로 저장돼요." + 개인정보 처리방침 링크
- 하단 "다른 이름으로 참여하기" 링크는 없음(2026-10-17 삭제)

### 개인 초대 링크의 자리가 이미 회원 계정인데 비로그인일 때

- "초대받은 그룹" 카드 + 콜아웃 "승인이 완료됐어요. 로그인하고 사용해요." + "로그인" 버튼만 보임
- 로그인하면 같은 링크로 돌아와 바로 그룹으로(이미 멤버)

## 데이터

- 로그인 상태: `request_join(code)` — 내 계정으로 새 멤버 참여 요청 (이름은 프로필 이름)
- 비로그인: 익명 세션을 만든 뒤 `request_join(code, null, 이름)` — 게스트로 새 멤버 참여 요청
- 그룹장이 승인하면 새 `Member`가 생기고 "OOO님이 [그룹명] 그룹에 참여했어요" 알림([13](13-notifications.md))
- 그룹장이 없는 그룹이면 요청 없이 바로 멤버가 된다(회원이면 그 사람이 새 그룹장)

## 액션 & 결과

| 액션 | 결과 |
|---|---|
| (로그인) "{내 이름}님으로 참여하기" | 참여 요청 → [06](06-join-group.md) "승인 요청중" 화면 |
| (비로그인) 이름 입력 후 "이 이름으로 참여하기" | 게스트로 참여 요청 → "승인 요청중" 화면 |
| "로그인" / "회원가입" | [01](01-login.md) 로그인·가입 → 마치면 이 링크로 복귀, 로그인 상태의 화면으로 |
| 뒤로가기 | 06 초대코드 입력 화면 |

## 예외처리

- 이름이 비어 있으면 "이 이름으로 참여하기" 비활성화
- 그룹 내 이름 중복 검사는 없음
- 그룹장이 미리 추가해 둔 사람이 이 화면으로 참여하면 같은 사람이 두 자리로 나뉠 수 있음 → 그런 사람에게는 개인 초대 링크를 보낼 것
- 이미 이 그룹에 보낸 요청이 대기 중이거나 거절됐으면 이 화면 대신 06의 승인 요청중 / 거절됨 화면이 먼저 보인다
