# 07. 참여하기 (멤버 매칭)

> 초대코드 참여(06)에서 **공용 코드**로 들어왔을 때만 거치는 화면(`screen-join-pick`). 그룹에 이미 등록된(앱 미가입 상태로 이름만 추가된) 멤버 중 본인이 있으면 선택하고, 없으면 새로 참여한다.

> ⚠️ **이 화면을 작성할 담당자는 반드시 확인**: [12-group-invite.md](12-group-invite.md)의 "앱 미가입 상태로 이름만 추가된 멤버(placeholder)"와 [06-join-group.md](06-join-group.md)의 "로그인 없이 참가(게스트)"는 데이터 구조상 완전히 동일함(`Member.userId`가 null, `Member.name`만 있음) — 매칭 대상자는 (1) 정식 로그인(이메일 가입)으로 들어와 `userId`가 채워지는 경우, (2) 로그인 없이 그대로 게스트(`userId`는 계속 null)로 남는 경우 둘 다 가능함(**구글·카카오 연동은 스펙에서 제외**, 2026-09-12). placeholder가 정식 회원으로 매칭되면 그 Member의 `userId`만 채우면 되고(id는 그대로 유지되어 기존 지출 기록이 자동으로 연결됨), 게스트로 참여하는 경우도 마찬가지로 별도 이관 로직 없이 그 Member를 그대로 씀. 로그인 없이 참가한 경우 계좌정보는 계속 없음. 배경: [PLAN-sep03-yunjung.md](../../PLAN-sep03-yunjung.md) "결정된 질문 9" 참고.
>
> ✅ **게스트 재입장 인증 확정 (2026-09-12)**: PIN 등 별도 인증 없음. sep10에서는 이 화면(`screen-join-match`)이 `screen-join-pick`으로 대체됨 — 초대코드 확인 후 그룹 멤버 목록에서 "본인이 누구인지" 고르거나(이미 `userId`가 채워진 멤버는 선택 불가), 없으면 (로그인 안 한 경우) 이름만 입력해 새로 참여, (로그인한 경우) 그냥 새 멤버로 추가됨. 재입장(같은 사람이 다시 들어오는 경우)도 이 화면에서 같은 이름을 다시 고르는 것으로 처리되며 본인 확인 절차는 없음.

- **담당자**: 민선
- **상태**: 작성중

## 목적

공용 초대코드로 들어온 사람이 "이미 그룹장이 미리 등록해둔 멤버 중 본인이 있는지" 확인하고, 있으면 그 자리로 연결하거나 없으면 새 멤버로 참여시키는 화면. 이 매칭이 있어야 그룹장이 앱 미가입 친구를 미리 추가해 지출을 나눠 기록해둔 내역이, 그 친구가 실제로 들어왔을 때 자연스럽게 연결된다.

## 주요 기능

- 그룹 멤버 목록 표시 — placeholder/게스트(`userId` 없음)만 선택 가능, 이미 계정이 연결된 멤버는 "이미 가입됨"으로 표시하고 선택 불가
- 목록에 본인이 없을 때 새로 참여
  - 비로그인 상태: 이름을 직접 입력해 참여
  - 로그인 상태: 입력 없이 내 계정 이름 그대로 새 멤버로 참여

## UI 구성요소

- 상단바: 뒤로가기(→ [06-join-group.md](06-join-group.md)), 타이틀 "참여하기"
- 안내 문구 (`jp-group-name`): "[그룹명] 그룹에 참여해요. 본인이 누구인지 골라주세요."
- 멤버 목록 (`jp-member-list`): 행마다 아바타 + 이름
  - `userId`가 없는(placeholder/게스트) 멤버: 클릭 가능, 체크박스 아이콘 노출
  - `userId`가 있는(이미 정식 회원으로 연결된) 멤버: "이미 가입됨" 텍스트만 노출, 클릭 불가
- (비로그인 시) "목록에 없으면 이름을 입력해주세요" 라벨 + 이름 입력 필드(`jp-new-name`) + "이 이름으로 참여하기" 버튼(`jp-add-btn`, 입력 전까지 disabled)
- (로그인 시) "목록에 없으면 새 멤버로 참여할 수 있어요" 안내 + "새 멤버로 참여하기" 버튼

## 데이터

- 대상 그룹: 06에서 넘어온 대기 중인 그룹 id
- **기존 멤버 선택** (`pickExistingMember`): 로그인 상태면 해당 `Member.userId`를 내 계정 id로 채움(`id`는 그대로 유지되어 기존 지출 기록이 자동 연결됨) / 비로그인이면 데이터 변경 없이 세션에 "그 자리로 본다"는 표시만 남김
- **새 이름으로 참여** (`joinAsNewName`, 비로그인 전용): 새 `Member`(`userId: null`, 입력한 이름) 생성, 그 자리로 세션 지정
- **새 멤버로 참여** (`joinAsNewMember`, 로그인 전용): 새 `Member`(`userId: 내 계정 id`) 생성
- 두 "새로 참여" 케이스 모두 "OOO님이 [그룹명] 그룹에 참여했어요" 알림 생성 ([13-notifications.md](13-notifications.md) 참고)

## 액션 & 결과

| 액션 | 결과 |
|---|---|
| 멤버 목록에서 placeholder/게스트 행 클릭 | 로그인 상태: 그 자리에 내 계정 매칭 후 그룹 내부로 이동 / 비로그인: 그 자리로 지정 후 그룹 내부로 이동 |
| "이미 가입됨" 멤버 행 클릭 | 아무 동작 없음 (선택 불가) |
| (비로그인) 이름 입력 후 "이 이름으로 참여하기" | 새 Member 생성 → 그 자리로 지정 → 그룹 내부로 이동 |
| (로그인) "새 멤버로 참여하기" 클릭 | 내 계정으로 새 Member 생성 → 그룹 내부로 이동 |
| 뒤로가기 | [06-join-group.md](06-join-group.md) 초대코드 입력 화면으로 복귀 |

## 예외처리

- 비로그인 상태에서 이름 입력이 비어 있으면 "이 이름으로 참여하기" 버튼이 비활성화됨
- 그룹 내 이름 중복 검사가 없음 — 같은 이름으로 여러 명이 각각 새로 참여할 수 있고, 이후 재입장 시 어느 쪽인지 구분할 방법이 없음(06/`conventions.md`의 스푸핑 트레이드오프와 같은 맥락)
- "이미 가입됨"으로 표시된 멤버의 실명이 그대로 노출되므로, 본인이 아닌 다른 사람이 그 이름을 보고 혼동해 별도 이름으로 중복 참여할 수 있음 (사소한 UX 리스크, 정책 결정 없음)
- 정상적으로는 이미 그룹에 속한 사람이 재입장하면 [06-join-group.md](06-join-group.md)에서 `isMe` 판별로 걸러져 이 화면까지 오지 않지만, 그 판별에 쓰이는 세션 정보(`viewAsMemberId`, 비로그인 기준)가 유실되면(다른 기기·브라우저 등) 이 화면에 다시 진입해 "새 멤버로 참여하기"를 눌러 같은 사람이 중복 멤버로 등록될 수 있음
