# 07. 초대 대기 멤버 매칭

> 초대코드 참여(06) 이후, 이미 그룹에 사전 등록된(앱 미가입 상태로 이름만 추가된) 멤버 중 본인이 있으면 선택해 매칭하는 화면.

> ⚠️ **이 화면을 작성할 담당자는 반드시 확인**: [12-group-invite.md](12-group-invite.md)의 "앱 미가입 상태로 이름만 추가된 멤버(placeholder)"와 [06-join-group.md](06-join-group.md)에서 결정된 "로그인 없이 참가"는 서로 다른 개념이지만 이 화면에서 만남 — 매칭 대상자는 (1) 정식 로그인(이메일 가입)으로 들어온 정식 회원, (2) 로그인 없이 들어온 참가자 둘 다 가능함(**구글·카카오 연동은 스펙에서 제외**, 2026-09-12). 두 경우 모두 placeholder 멤버와 매칭되면 placeholder의 지출 기록(`paid_by`/`expense_participants`)이 매칭된 사용자의 id로 이관되어야 함. 로그인 없이 참가한 경우 이관 후에도 계좌정보는 여전히 없다는 점을 유의. 배경: [PLAN-sep03-yunjung.md](../../PLAN-sep03-yunjung.md) "결정된 질문 9" 참고.
>
> ⚠️ **sep10 프로토타입 구조 반영 필요**: sep10에서는 이 화면(`screen-join-match`)이 `screen-join-pick`으로 대체됨 — 초대코드 확인 후 그룹 멤버 목록에서 "본인이 누구인지" 고르거나, 없으면 (로그인 안 한 경우) 이름만 입력해 새로 참여, (로그인한 경우) 그냥 새 멤버로 추가됨. 기존에 가정했던 "닉네임+PIN" 재입장 인증은 sep10 코드에 없음 — 정식 결정인지 미확인 상태([06-join-group.md](06-join-group.md) 참고).
